# andamentum.references — notes for Claude

Moved from the root `CLAUDE.md`, word for word. Claude Code loads this file when it reads files in this directory.

## Overview

- `andamentum.references` — reference checking for a draft, for any citation style. `await check_references(text, *, sections=None, hints=None, model=None, lookup=True)`. Four stages. **Find**: the reference list (numbered or not — an unnumbered author-year list is split by paragraph, keeping lines with a year or DOI) and every candidate citation of every kind: `[3]`, `(3)`, superscript numbers (from `hints` the caller reads out of the file's formatting — whetstone's `docx/citation_hints.py` reads Word superscript runs and Zotero/Mendeley/EndNote field codes), digits glued to words (for texts that lost their formatting), author-year parentheticals and narratives, reference-manager fields. **Decide** (`decide.py`) evidence first: each style is scored by candidates that point at a real entry *after* rules rule out distractors (exponents after units, affiliation marks in the author block, figure/table/equation/statistic numbers — counted as support, the distractors once made superscripts look like a rival to nine bracket citations); a reference-manager field settles the style outright; a style leads by ≥3 and 3:1 (or is the only kind present) and must agree with the list's shape (numbered ↔ numeric). Per candidate, rules again — including *the next new number in citation order* after a word, which reads glued digits deterministically (gpt-5.4-nano rejected two such in every run). **Only what the evidence leaves open goes to a model**, and only when `model=` is passed: one style call, or candidate batches of ≤12, each item a ±60-character excerpt, answers flat (`style: Literal`, `citation_ids: list[int]`) — sized for local models; strictly sequential. Without a model the open cases are reported as undecided/unjudged, never guessed, and "never cited" is withheld while any candidate is unjudged. A repeated citation ("earlier work2.") is deliberately NOT a rule: punctuation cannot tell it from a label ("day3.") without a domain word list. **Check**: cited-not-listed, never-cited, duplicates; numeric: first-citation order; author-year: year mismatch (reported once — the entry is not also "never cited"), ambiguous same-author-same-year without a/b. Surnames match the entry's first author, whole then dropping leading words ("Nguengang Wakap", sentence-initial "As Turro"). **Look up** (Crossref, default on): only entry text sent; a record matches only when its title is (fuzzily) in the entry; up to three searches (whole entry, `query.title`, year ±1) because Crossref's whole-entry ranking missed three Nature/Science papers on a real 51-entry list; any issued/online/print year counts (online-first vs issue year gave eight false alarms); a same-titled record whose year and author both differ, or whose author differs with no volume/page agreeing, is a namesake; a failed call is `service_error`, unchecked, never reported as wrong. **Measured** on `benchmarks/references` (13 real CSL styles rendered by citeproc-py — APA, Harvard, Chicago author-date, Elsevier-Harvard, Springer, Nature, Cell, IEEE, AMA, NAR, PLOS, BMJ, MLA — plus formatting-stripped variants of the superscript styles, planted errors and distractors): evidence alone reads every style and every planted error with zero false alarms except the flat texts' genuinely ambiguous labels, which it leaves unjudged; MLA (author-title, no year) is correctly undecided. **Pandoc keys** are a sixth style, `pandoc_keys`: a bracketed group of `@key`s (`[@smith2020]`, `[see @lee2019, p. 4; @park2021]`, wrapping onto the next line but not across a blank one; not a Markdown link, not an e-mail address) against a list whose lines open with the key (`[@smith2020] Smith, J. …`). A key names its entry exactly, so it is decided by evidence and checked with no resolution step: cited-not-listed, never cited, `duplicate_key`. `LOOKUP_KINDS` (exported) is the one list of problem kinds that only the lookup finds; every other kind is offline, and whetstone derives "offline" from it rather than keeping a copy. **Notes styles** (Chicago notes-and-bibliography and kin) are a fifth style, `notes`: whetstone's `citation_hints` reads each Word footnote/endnote mark's position — counted with the projection's own rules, since the mark is not a character — and the note's text from `footnotes.xml`/`endnotes.xml`; Markdown `[^1]` footnotes are read from the text itself. `notes.py` reads a note as full (year and title; the year taken from parentheses first, so a short form's page "1755" is not a year), short, `Ibid.`, commentary, or unclear (to the model, ≤300 characters of the note); names in notes run first-name first, so the surname is the author part's last word, after signal words ("See also", "Cf."). A note is matched to the bibliography by first-author surname AND title (one author, several works). Checks: note cites a work not in the bibliography, entry never cited, year differs, `Ibid.` with no single source before it (first note, after commentary, or after a note citing two works), and — with no bibliography — a short form before the work's full note; the full notes then stand in for entries in the Crossref lookup. A comment on a note lands on the word before its mark. Measured: both notes documents in the test set (with and without a bibliography) read by evidence with every planted problem found and no false alarm.
**PDF input** reaches the checker with the same evidence as Word: whetstone harvests with `preserve_superscripts=True` (below), and its baseline writer turns `<sup>` into superscript runs, Markdown footnotes into real Word footnotes (`whetstone/docx/footnotes.py`), and decodes docling's HTML entities (`&amp;` had reached the reviewer's text literally, and "Li &amp; Durbin" read as a citation of Durbin). A converted PDF's reference list arrives merged and broken at arbitrary points, so `split_entries` reads the list as one stream: numbered entries are accepted as a rising sequence (steps of 1–3, cut only after a whole entry, line-start numbers kept even when repeated), unnumbered ones split before a new first author ("Surname, I." or "Surname AB,") once the text since the last cut holds a year; a names-only line, or any line after an entry that has no year yet, continues it. A numbered list that starts above 1 while the text cites below it is ONE problem ("the list starts at entry 3") — docling had dropped two BMJ entries. Measured via `evaluate.py --pdf` (LibreOffice renders each test document): 17/18 read with only the planted problems; the 18th is that true report.
Surfaced by `andamentum-whetstone references [--model M] [--no-lookup]` (`whetstone/references_check.py`); the summary says how the document cites and why candidates were set aside.

## Decision model (open citation candidates)

`check_references(..., decision_model=None)` (keyword-only; the CLI flag is `andamentum-whetstone references --decision-model NAME`). With an opened `core.decisions.DecisionModel`, the candidates the rules leave open are answered by it instead of the language-model batch: one `noul` question (`gate.QUESTION_TEXT`) per candidate, sent together with `ask_all`, and `p >= 0.5` means citation. No thresholds, records or escalation; if the call fails the candidates are "not judged". With `None` nothing changes (`tests/test_decision_gate.py`).

## Layering

- `references` depends on `pydantic`, `httpx`, `rapidfuzz` and — for its two model calls and the decision-model replacement only — `core` (`AgentDefinition` / `resolve_model`, with an explicit `model=` and no default; `core.decisions`). It MUST NOT import any other andamentum sub-module (a test in `references/tests` enforces it). `whetstone` MAY depend on it (`references_check.py`, `docx/citation_hints.py`, the `references` subcommand, the goal loop's `goal/references.py`, and `v3/digest.py:read_citations` — the review's citation summary, read with no model and no lookup and shown as one `CITATIONS:` line to criteria with the `citations` facet). It is the package's ONLY citation reader: the review's own marker regexes, `has_citation` and `goal/citations.py` were deleted in its favour, and a second reader would disagree with it about one document.

## Network helpers (retraction, cited-work resolver, URL health)

Added for the compose harness's citation checks; each is usable alone, with no draft.

- **`ReferenceHttp`** (`http.py`) is the one client for these calls. It takes an injected `httpx.AsyncClient` (tests pass a `MockTransport`; it closes only a client it created) and an optional `Cache` — a two-method protocol, `get(key) -> bytes | None` and `put(key, bytes)` — so the harness can pass its project cache. Cached: a Crossref 200 or 404 and a settled URL status (`ok`, `not_found`, `client_error`). Never cached: service errors, timeouts, server errors, DNS failures (asking again may succeed). `mailto` goes in the query and User-Agent as in `lookup.py`, and only when the caller passes it. It reuses `lookup._get` (one retry on 429/5xx).
- **`lookup_retraction(doi, *, http)`** (`retraction.py`) reads Crossref's `updated-by` on the cited work (each notice has `type`, `source` — `retraction-watch` or `publisher` — and the notice DOI); a DOI that is itself a notice shows `update-to` and sets `is_notice`. Only retraction (withdrawal, removal folded in), expression of concern and correction (erratum, corrigendum folded in) are reported; other update types are ignored. `RetractionStatus.retracted` is the error case; the other kinds are warnings for the caller to grade. `service_error` / `not_found` mean unchecked, not sound.
- **`resolve_cited_work(*, http, doi, title, authors, year)`** (`cited.py`): for a caller that holds the parts, not a printed entry. Stage one fetches candidates (by DOI, else `query.bibliographic` on the assembled text, then `query.title`); stage two is `lookup._judge`, so the rules are the entry lookup's (title must appear, namesakes and reposts handled). A DOI with no title is `found` if it resolves. Returns `LookupResult` with `entry_number=None`.
- **`resolve_entry(entry, *, http, title="", compare=True)`** (`cited.py`): the same two stages for a `ReferenceEntry` already read from a list (`resolve_cited_work` builds an entry from its parts and calls it). The harness `citations` check uses it for plain-text bibliography entries.
- **`ReferenceHttp(url_check=...)`**: the URL-safety predicate (default `core.url_safety.is_safe_url`, which resolves DNS; looked up when a URL is checked, so a test that patches `andamentum.references.http.is_safe_url` covers clients built by other modules too). A harness benchmark replaces it with a scheme-only check so recorded fixtures for `.example` hosts run offline; production never does.
- **`ReferenceHttp.check_url(url)`** → `UrlHealth(status, http_status, final_url, detail)`; statuses `ok`, `not_found` (404/410), `client_error` (other 4xx — usually a bot block, not a dead link), `server_error`, `timeout`, `dns_failure`, `blocked` (SSRF), `error`. HEAD first, GET when HEAD is not a success (servers answer HEAD wrongly). It does not use `fetch_with_safe_redirects`: that one reads a body, and a health check needs only the status line. It follows redirects itself and runs `core.url_safety.is_safe_url` on every hop, the same defence.

Tests: `tests/test_http_lookups.py` with synthetic recorded Crossref JSON in `tests/fixtures/`; no network.

## The work record

`works.py` holds `Work` (identifiers doi / arxiv_id / pmid / pmcid / openalex_id / s2_id / url, bibliographic fields, `oa_url`, `access`, `retracted`, `licence`), the identifier normalisers (`normalise_doi`, `normalise_arxiv_id` with version stripping, `normalise_pmid`, `normalise_pmcid`, `normalise_openalex_id`, `normalise_s2_id`), `canonical_url` (scheme and host lower-cased, `www.` and default port dropped, `utm_*` and click-tracking parameters removed, no fragment or trailing slash; http and https stay distinct), `Work.identity_keys()` (DOI, arXiv, PMID, PMCID, OpenAlex, Semantic Scholar, URL, then title+year, the one soft key), `merge_works` (the licence describes the abstract and travels with it: when one record is `no_redistribute` and the other holds an abstract, the redistributable abstract and its licence win, so a Semantic Scholar copy never takes away text OpenAlex gives freely; otherwise the restrictive tag wins), `works_compatible` and `Work.to_csl()`. Identifiers are normalised on construction and a non-empty value that is not one raises. A doi.org, arXiv, PubMed, PMC or OpenAlex URL fills the identifier it names when none is given. `deep_research.v2` is its first user. Pure: it imports nothing from andamentum.
