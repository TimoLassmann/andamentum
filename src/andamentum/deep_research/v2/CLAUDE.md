# deep_research v2 — notes for Claude

The new, evidence-first research engine. The legacy pipeline in the parent package stays as it is for `epistemic`; v2 is a separate entry point. Layering: v2 imports `core` and `references` only, never `epistemic`, `document_store`, `compose` or `whetstone`.

Entry point: `await research(question, *, mode, model, decision_model=None, store=None, budget=Budget(), sources=SourceConfig(), config=PRESETS["baseline"], frozen=None, source_client=None, progress=None, clock=time.monotonic) -> ResearchResult` (`graph.py`, exported from `v2`). From the shell: `andamentum-research v2 "QUESTION" --mode {web,scholarly,both} --model M [--preset baseline|fast|criteria] [--decision-model NAME] [--store PATH] [--cache PATH] [--searxng-url URL] [--sources ...] [budget flags] [--json|--md] [--out FILE]` (`cli.py`). Over MCP: `andamentum-research mcp --store PATH` (`mcp_server.py`).

## What exists

- `types.py` — every record of a run: `SubQuestion`, `Criterion`, `Candidate` (a `references.Work` plus where it came from), `CandidateScore`, `Passage`, `Finding`, `Conflict`, `Coverage`, `VerifyFlag`, `Budget`, `RunStats`, `ResearchResult` (with `cited_work_ids()` and `to_csl()`). A `Passage` is content-addressed (`passage_id = sha256(work_id + text)`) and an exact slice (`end - start == len(text)`); both are checked at construction. A report cites findings as `[F12]`; `cited_work_ids` reads only that bracket form.
- `identity.py` — `merge(candidates)`: one candidate per work. Keys come from `Work.identity_keys()` (DOI, arXiv id, PMID, PMCID, OpenAlex id, Semantic Scholar id, canonical URL, title+year). A shared hard key merges, transitively; the title key merges only when `works_compatible` (no identifier both sides hold disagrees), so a preprint and its published version stay two works. A title key needs a year and 15+ normalised characters.
- `store.py` — `ResearchStore(path)` / `ResearchStore.in_memory()`. See below.
- `sources/` — the adapters, see below.
- `ask.py`, `criteria.py`, `read.py`, `coverage.py`, `write.py`, `verify.py` — the workers, see below.
- `steps.py` — the glue each graph node calls (plan, queries, search, admission, a screening round, expansion, what to read, conflicts); `graph.py` — the nodes, `ResearchDeps`, `ResearchState`, `research()`; `cli.py` — the `v2` subcommand; `mcp_server.py` — the MCP server; `bench/` — the benchmark and experiment framework.
- `config.py` — `ResearchConfig`, `config_hash`, the strategy registries and `PRESETS` (`baseline`, the default, `fast`, `recall` and `criteria`); `strategies.py` — one small implementation per strategy name; `frozen.py` — `FrozenInputs` and `capture`. See "Configuration" and "Frozen inputs" below.

The work record itself (`Work`, the identifier normalisers, `canonical_url`, `merge_works`) lives in `references/works.py`, the package's citation currency; do not write a second one here.

## The store

One SQLite file (WAL) and a `blobs/` folder beside it; the caller always names the path. No default location, nothing under the home directory. A lab can keep one store for all projects; compose passes `<doc>.harness/research.db` (Word) or `<bundle>/research.db` (bundle), whetstone's `--novelty-store` a path of the caller's choosing. `in_memory()` leaves nothing behind.

- **Blobs** are named by sha256. Up to `INLINE_BLOB_LIMIT` (16 KiB) they sit in the `blobs_inline` table, above it in `blobs/<aa>/<sha>` (written to a temporary name, then renamed). Every `*_blob` column holds a digest.
- **HTTP cache**: `cache_key(source, url, params)`, `cache_get` (None once the TTL has run out), `cache_put`. TTL constants: `TTL_SEARCH_S` 7 days, `TTL_METADATA_S` 30, `TTL_FULL_TEXT_S` 180. Hits and misses are counted on the store (`cache_hits`, `cache_misses`) for `RunStats`. A row tagged `no_redistribute` is usable inside the store but `iter_cache()` (the export path) leaves it out, and `Work.to_csl()` omits the abstract of such a work. `reference_cache()` returns the store as the `references.http.Cache` protocol, so Crossref lookups share the cache instead of keeping their own.
- **Shared read-through cache**: `ResearchStore(path, shared_cache=other)` (also `in_memory(shared_cache=)`; `research(http_cache=)`, `--cache PATH` on the v2 CLI, `bench freeze` and `bench experiment run`). An own miss (or an expired own row) reads through to the shared store: a live entry there is copied into this store with its original `fetched_at` (the TTL keeps counting from the fetch) and counted as a hit (`shared_hits` too); `cache_put` writes to both. Every path goes through `cache_get` / `cache_put`, so adapters, `keep_text`, Crossref (`ReferenceCache`) and the retraction check are all covered. `any_age` reads (offline, frozen) never consult the shared store, so a frozen run sees only its snapshot. A row's licence travels with the copy: `no_redistribute` entries are usable in both stores and left out of `iter_cache()` in both. The item store therefore holds exactly the entries it used, and a snapshot's `store.db` stays self-contained. `import_cache(source_db)` merges another store file's `http_cache` rows and blobs (opened read-only; freshest `fetched_at` per key wins; an expired row, an unreadable blob and a row no fresher than the held one are counted, not imported; counts by `source`). `research(http_cache=)` is refused with `frozen=` or an open `store` (open that with `shared_cache=`).
- **Works**: `upsert_work` merges with every stored work sharing any identifier (all seven have a unique index; absent identifiers are NULL). A record that bridges two stored works merges them into the older one; the other id keeps resolving (`work_aliases`, `resolve_work_id`). Passages keep the id they were addressed with, so `passages_for_work` includes those of the aliases, and anything that holds an old id resolves it through the store. A merge only raises `access` and `retracted`; `set_work_state` is the one way to overwrite them after a fresh check.
- **Runs**: `start_run` / `finish_run`, `add_run_item(kind, ref_id, data)` (a row with the same kind and ref id is replaced; kinds are `RunItemKind`), `log_decision` (audit only; nothing reads decisions back during a run).
- Schema changes are migrations by version number in `_MIGRATIONS`; a database from a newer version is refused with `StoreError`. No shims for old development files.
- One writer per process: every public method takes the store's lock.

## Configuration: strategies and presets (`config.py`, `strategies.py`)

The rule this exists for: a simple baseline first; a more complex variant (LLM-written criteria) is accepted only when it measurably beats the baseline on the same inputs. `ResearchConfig` (frozen pydantic, `extra="forbid"`) names one strategy per slot plus every cap and the determinism knobs; the engine calls the slot, never an implementation, so an experiment adds a strategy object in `strategies.py`, an entry in the slot's registry in `config.py` (`SCREENS`, `REFINES`, `RANKS`, `PASSAGES`, `EXPANDS`, `FACETS`) and a preset, and leaves the engine alone. Unknown names and impossible combinations (refine `on` without a criteria screen) are refused at construction.

| Slot | `baseline` (the default) | `criteria` (the first build, kept as an arm) |
|---|---|---|
| screen | `generic`: ONE `noul` per candidate, `relevance_question` "Is this item relevant to the question: <sub-question>?", state `item_state` = title, abstract or snippet, year, venue (no sub-question in the state); without a decision model the LLM answers the same `Question` (one call per candidate, through `Screener.ask`, so cached and logged like every screening answer) | `criteria`: `Screener.score_candidates` as built |
| drop rule | kept when p(relevant) >= `drop_below` (`GENERIC_DROP_BELOW` 0.5); score = p | `combine` as built |
| refine | `off` | `on`: `Screener.refine` as built |
| rank | `rrf`: per sub-question, Σ 1/(`RRF_K` 60 + rank) over each source's list (`Candidate.source_ranks`, the best 1-based place a work reached in that source; a citation hop is its own list, `openalex:citations`) and the screen-score list (ties share a rank); a work kept for several sub-questions takes its best | `score`: best screen score, as built |
| caps | `screen_per_subquestion` 25 a round; `read_per_subquestion` 8 over the whole run (best-ranked unread first); always inside the `Budget`'s own bounds | `None`: the budget's caps only |
| expand | `citations`: the `expand_seeds` 3 best kept works, at most `expand_per_round` 20 new candidates (and never more than `Budget.expand_per_round`) | `citations` with `MAX_EXPAND_SEEDS` 5 and the budget's 40 |
| passages | `lexical`: BM25 (`BM25_K1` 1.5, `BM25_B` 0.75, idf `log(1+(N-df+0.5)/(df+0.5))` over the work's own passages) against the sub-question text, terms casefolded, 3+ letters, `read._STOPWORDS` out, a plural `s` folded; the best `passages_per_work` 4 with a score above 0, best first; no model call | `criteria`: `read.select_passages` as built |
| facets | `off`: no criteria compiled, none in extraction, coverage or the writer; `result.criteria` is `{}` | `on`: compiled at Plan and carried through, as built |
| verify | `model`: every report sentence's claim support goes to the model | `model` |
| queue | `arrival`: waiting (work, sub-question) pairs are screened in the order they were found; the `recall` preset uses `source_rank` | `arrival` |

**Round 2: the `fast` preset** is the baseline with two strategies swapped and nothing else (`tests/test_round2.py::test_fast_is_the_baseline_with_two_strategies_swapped`): screen `generic_prefilter` and verify `code_first`. The baseline stays the default; `fast` replaces it only if the round-2 experiment accepts R1 and R2 (`bench/experiments/round2.yaml`).

- **`generic_prefilter`** (`strategies.GenericPrefilterScreen`): a sub-question's candidates (at most `screen_per_subquestion` a round) are ranked by BM25 (`bm25_scores`, the passages' code, the candidates as the collection) of title + abstract-or-snippet against the sub-question text, ties in arrival order; the best `PREFILTER_TOP` (12) go to the generic question exactly as the `generic` screen asks it, every other candidate is dropped in code (`kept` False, score 0, reason "dropped: below lexical pre-filter (BM25 rank r of n; ...)") and logged as a `candidate` run item like the rest. With 12 candidates or fewer it is the `generic` screen, request for request.
- **`code_first`** (`verify.supported_in_code`): a sentence is supported in code when at least `CODE_SUPPORT_MIN_OVERLAP` (0.8) of its content tokens occur among the tokens of the quotes it cites. Content tokens (`verify.content_tokens`): casefolded, a number kept exactly as written ("3.5", "1,200"), anything with a digit kept, other words of three letters or more minus `read._STOPWORDS`; no stemming. A sentence with no content token is left to the model. Only the other sentences are asked (`claim_support`, as before). `RunStats.verify_by_code` / `verify_by_model` count both ways for every preset (the baseline has 0 by code). The rule is a pre-registered gate input, so it is not tuned: a sentence with one wrong number among ten tokens still reaches 0.9.
**Round 3: the `recall` preset and the `queue` slot** (`strategies.QueueStrategy`, registry `config.QUEUES`). `recall` is the baseline with `queue: source_rank` and nothing else (`tests/test_round3_engine.py::test_recall_is_the_baseline_with_one_strategy_swapped`). The slot decides the order in which a round's waiting pairs are offered to `steps.round_robin` and its `screen_per_subquestion` cap (25 a round), and nothing else: `arrival` is the engine as it was (Europe PMC's works, which arrive first, take the first 25 slots of a sub-question), `source_rank` puts the pairs best first by `strategies.source_rank_score` (reciprocal-rank fusion, Σ 1/(`RRF_K` 60 + rank) over the candidate's `source_ranks`, a citation hop being a list of its own; ties keep arrival order; interleaving across sub-questions is unchanged). The graph's `Screen` node applies it to the screening call only: `state.pending` stays in arrival order, so ties are always arrival-ordered. `source_rank_score` is the one copy of that rule: `bench.freeze.prefetch_targets` (which works get their text prefetched) imports it. The `recall` preset and the any-term arXiv query were adopted for test in round 3 (see "Round 3" below); they are not defaults.

- The `verify` and `queue` fields are left out of `canonical_json` while they hold `model` / `arrival` (`_UNHASHED_AT_DEFAULT`), so the baseline's hash is the one recorded before the slots existed (`test_the_baseline_hash_is_the_one_recorded_before_the_verify_slot_existed`; `test_round3_engine.py::test_the_baseline_hash_does_not_move_and_carries_no_queue`).
- **The baseline is what it was**: `tests/fixtures/baseline_preset_trace.json` is the baseline preset's trace (every model request in order and the evidence table, four scenarios) recorded from the engine at commit f339357 with `preset_trace`; `test_the_baseline_reproduces_the_engine_before_round_two` compares it (with `decision_cache=False`, since the cache adds the determinism probe and drops repeated requests).

- Criteria are compiled at Plan only when some chosen strategy `needs_criteria`; the baseline makes no criteria call at all.
- `config_hash(config)` (also `config.config_hash()`) is sha256 of `canonical_json` (sorted keys, no whitespace, `name` and `description` left out: two configurations that do the same thing hash the same). The run records `research_config`, `config_hash` and the frozen digest in `runs.config_json`; `ResearchResult` carries `config_name`, `config_hash`, `frozen` and `skipped`. `tests/test_presets.py` pins the baseline's hash: a change to it changes what every recorded hash means.
- **The `criteria` preset is the first build, request for request.** `tests/test_presets.py::test_the_criteria_preset_reproduces_the_first_build` compares four runs over `engine_world` (scholarly with and without a decision model, both, web) with `tests/fixtures/criteria_preset_trace.json`, recorded from the code at commit cf61b6e by `tests/preset_trace.py`: every language-model call (instructions and prompt), every decision request (state and questions), in order, and the evidence table. `preset_trace.counted_uuids` makes the store's work and run ids a counter while tracing, because a tie between two works is broken by that id and uuids differ run to run.
- **Determinism knobs**: both presets send `temperature` 0 and `seed` `DEFAULT_SEED` (42) with every language-model call (`ResearchConfig.model_settings()` -> `Asker.model_settings` -> `core.agents.run_agent_with_usage(model_settings=...)`), so arms differ only in their strategies. Measured 2026-10-06 (5 keyword queries as structured output, the same prompt repeated): the settings are on the wire (`temperature: 0.0, seed: 42` in the OpenAI-compatible request); a local GGUF model (`openbmb/minicpm5-2b:q8_0`) gave identical output twice; a local nvfp4 safetensors model (`gemma4:e2b-nvfp4`) gave 3 different outputs of 3, and so did the cloud `gemma4:31b-cloud` (closer to each other than at the default settings, still not identical). So repeat stability must be measured, not assumed, for the round-1 models. The decision model answered one state the same twice (`nimble:9b`, `tests/test_live_determinism.py`, marker `ollama`).

## Frozen inputs (`frozen.py`)

`capture(question, *, mode, model, store, decision_model=None, budget, sources, config, source_client=None, progress=None, clock=time.time, retractions=True) -> FrozenInputs` runs Plan and one round of Search live, with the engine's own steps (`steps.plan`, `write_queries` with `budget.queries_per_subq`, `search`, `admit` into *store*), then asks Crossref once for the retraction status of every candidate's DOI (failures in `retraction_unchecked`, not `degraded`). `FrozenInputs` holds the question, mode, `captured_at`, sub-questions, queries per sub-question, the merged candidates (full `Work` records with `source_ranks`), `degraded`, the models and sources (secrets left out) and the capture's run id. `save(path)` / `load(path)` (one JSON file; a different `version` is refused); `digest()` is sha256 of its canonical JSON. The snapshot is the JSON plus the store it was captured over (its cache).

**What `bench freeze` caches** (rules recorded in each snapshot's `meta.json`): search results for every candidate, but full text and the references and citations (the scholarly ones among them) only for the best `PREFETCH_TOP_K` (20, `--prefetch-top-k`) candidates of each sub-question by source search rank (`freeze.prefetch_targets`, one set for both; warming the hops of every candidate spent OpenAlex's keyless daily budget within two or three items, 2026-10-06, so a hop from a work outside the set is an offline miss for every arm) (`freeze.source_rank_score`: reciprocal-rank fusion over `Candidate.source_ranks`, never an arm's score; ties keep admission order). Every other candidate stays abstract-level: a frozen run that reads one meets `FROZEN_TEXT_REASON` ("not available in the frozen set (abstract only)"), an `offline` miss counted in `skipped`, the same for every arm; `meta.json` lists `prefetched_works` and `not_prefetched_works`. Items freeze up to `--concurrency` at a time (see Benchmark), their requests spaced through one `SharedPacing`; inside an item the retraction checks, the text fetches and the citation hops run together (the client keeps each source's spacing and in-flight cap). A rate-limited hop marks the snapshot `incomplete` in `meta.json` (status `incomplete`, exit 2, its inputs kept as they are); `bench freeze --rewarm` asks again for the failed hops and texts into the snapshot's own store and never touches `frozen.json`. `meta.json` also records `pdf_extraction`, the extractor per fetched URL (`extractors`, `extractor_counts`), the concurrency and the item's wall time; the printed report ends with the process wall time, CPU time and peak RSS.

**Shared cache and what the freeze reports** (`--cache PATH`, `http_cache=`): the snapshot's `store.db` is opened with the shared store as `shared_cache`, so a request any earlier item or freeze made costs no network. `meta.json` records `http_cache` (`shared_cache`, `hits`, `misses`, `hit_rate`, `served_by_shared_cache`, `network_requests` by source) and `citation_lookups` (`top_k`, `candidates`, `works_looked_up`, `works_not_looked_up`: the references and cited-by hops cover only the `prefetch_targets` set, never every candidate). The printed report adds each item's network requests per source and cache hit rate, and a total line. The Crossref retraction check is the one lookup that still covers every candidate with a DOI (so an offline arm never reads a retracted work); once cached it costs nothing.

`research(..., frozen=snapshot)`: the question and mode must be the snapshot's; Plan takes its sub-questions (no LLM call), Search round 1 admits its candidates and records its queries (no live search), later rounds search nothing (they screen what still waits and what expansion brings). Everything else runs over an **offline** `SourceClient` (built by `research`, or passed with `offline=True`; a live client is refused): every request is answered from the store's cache, at any age, or not made. Expansion uses cached citation responses only (a miss is `ExpandOutcome.skipped`), reading uses cached texts and else the abstract the record carries, the retraction check and the link and DOI checks use cached answers only (a miss is "not checked", never "fine"). `ResearchResult.skipped` lists the misses per source or host. A frozen run makes no network request (`tests/test_frozen.py` makes every real transport fail the test). Pass the store the snapshot was captured over (and warmed: `bench freeze` prefetches texts), or there is nothing cached to read.

**Round 3 additions to frozen inputs.** `capture(plan=snapshot)` takes another snapshot's sub-questions and queries (the planned filters follow from the sub-questions by code) and calls no model of any kind: none is opened, `model` may be `None` (`test_capture_with_a_plan_takes_the_queries_and_calls_no_model`; the run records `plan_from`, the plan's digest). `capture(tolerate_failures=("semantic_scholar",))` counts the failed searches of the named sources in `FrozenInputs.search_failures` and `tolerated` instead of `degraded`; any other failure still makes the snapshot unusable. `FrozenInputs` also records the search accounting, `searches` and `search_failures` per source, `result_counts` (results per source and query) and `search_s` (seconds in `steps.search`); these accounting fields are left out of `digest()` (it names the inputs, not how the capture went), and a snapshot written before they existed has the same digest as ever. A frozen run admits its candidates through `steps.restore_licensed_text`: the text of a `no_redistribute` work (its abstract and the candidate's snippet) is read back from the snapshot store's work record, because the snapshot file carries none, so the generic screen sees what a live run saw (`test_the_screen_state_of_a_frozen_s2_only_candidate_equals_a_live_run_and_no_dump_has_the_text`). `ResearchResult.screening` lists one `ScreeningEntry` per (work, sub-question) pair the run held, in arrival order: identifiers, title and year (`identity()` gives a `Work` for `metrics.work_matches`), `source_ranks`, `p` (`None`: never screened), `kept` and the work's final rank among `works`; it is what the loss table reads.

## Criteria: query-dependent screening (`criteria.py`, spec §4)

This is the `criteria` preset's screen, refinement, passage selection and facets; the `baseline` preset uses none of it. An LLM writes the screening rubric once per sub-question; the scorer applies it to every candidate. `Screener(asker=...)` is the run's screening service. Its model calls go through `ask.Asker`, so they are counted in `RunStats` and checked against `Budget`; an exhausted bound raises `BudgetExhausted`.

- **Compile** (`Screener.compile`, one-off `compile_criteria(sub_question, *, model, question="")`): one LLM call, flat schema `CriteriaDraft{criteria: [{text, kind, weight, applies_to}]}`. Code assigns ids `<subq>-C<n>`. The rules are checked in code (`validate_criteria`):
  - 3–8 criteria;
  - each criterion is one question ending in `?` and at most 200 characters;
  - no compound form: "and/or", "as well as", or "and"/"or" opening a second clause (`criterion_problems`; this is a pattern check, it cannot judge meaning);
  - no duplicates (same normalised word set);
  - at least one `must` judged on the candidate, because screening needs one.

  A broken answer is re-asked once, with the problems as feedback. A second broken answer raises `CriteriaError`.
- **What yes means** depends on scope and kind (`_OUTCOMES`, sent as the noul `criteria`). A candidate `must` is "yes" when the title and abstract show it holds *or do not rule it out*, so missing information keeps a candidate (recall first). An `exclude` is "yes" only when the text *clearly* shows it. Passage criteria are "yes" when the passage shows it.
- **Score**: ONE request per candidate. Each candidate-scope criterion is a `noul` question, plus `SOURCE_TYPE_QUESTION`, a `choice` whose option names are the `SourceType` literals, so no mapping is needed. The state is the sub-question, title, abstract (or snippet), year, venue and found_by, clipped at `MAX_STATE_CHARS`. Without a decision model the LLM answers the *same* `Question` objects in one call (labels C1..Cn, yes/no). `LLM_ANSWER_P` maps yes to 1.0 and no to 0.0, as in `Asker`: a language model's probability is not invented. Everything after the scorer is one code path. Answers are cached per run by (state hash, `question_hash`), so a candidate seen again, or a re-score after a revision, asks only the questions it has not answered.
- **Combine** (`combine`, `_judge`): any `exclude` with p >= `EXCLUDE_DROP_AT` (0.5) drops. Any `must` with p < `MUST_DROP_BELOW` (0.2) drops. Otherwise score = Σ w·p / Σ w over must and should. Every reason names the criteria and their p. The source type is recorded, never used to drop. `rank` puts kept candidates first, by score. `boundary_margin` is the distance in probability to the nearest rule that would flip the decision: for a dropped candidate, the largest violation.
- **Refine** (`Screener.refine`, called by `Screener.screen`) runs at most once per sub-question per run; the bound is held in the screener.
  - The LLM reviews the `REFINE_SAMPLE` (6) candidates with the smallest margin, one call each. A tie goes to the lowest-scored kept and the highest-scored dropped candidate.
  - With `REFINE_MIN_DISAGREEMENTS` (2) or more disagreements, the LLM revises the rubric once, with the same validation and one re-ask. A revised criterion with unchanged text keeps its id; a new one gets the next number. The round is then re-scored.
  - Statuses: `agreed`, `revised`, `revision_unchanged` and `revision_rejected` (the revision broke the rules twice, so the old criteria stand and the problems are recorded). `already_refined` asks nothing. `too_few_candidates` does not use up the one refinement.
- **Passages** (`Screener.score_passages`, `select_passages`): the passage-scope criteria plus `relevance_criterion` ("does this passage bear on the question: …?", a `must` of weight 3), judged by the same rules. `read.select_passages` uses this with a decision model. Without one it makes a single batched LLM pick instead.
- **Logged**:
  - every scorer answer: a `decisions` row per question (steps `screen`, `passage`; the LLM scorer's rows carry the LLM id and an empty digest), and every review (`refine_review`);
  - every criteria version: a `criterion` run item `<subq>/v<n>` with its origin (`compiled`, `given` or `revised`), the rejected attempts, or what it revises and the reviews;
  - every candidate decision: a `candidate` run item `<subq>/v<n>/<work_id>` with the criteria version and the margin.
- One-off `score_candidates(candidates, criteria, *, subquestion, decision_model=None, model=None)` scores outside a run, over a throwaway in-memory store and without refinement. It needs an *opened* `DecisionModel`, not a name.
- Candidates must carry their store `work_id`: upsert them before screening.

## Sources (`sources/`, spec §3)

One protocol, six adapters, one shared HTTP client. `Source.search(query, *, limit, filters)` raises `SourceError` and never returns `[]` for a failure; `TextSource.fetch_text(work)` returns `FetchedText` or `None` ("no text here", not an error); `ExpandingSource.references/citations(work, *, limit)`. They are separate runtime-checkable protocols, so the engine asks `isinstance`. `SourceError` carries `source`, `reason`, `kind` (`http`, `transport`, `rate_limited`, `refused`, `parse`, `config`, `offline`), `status`, `url`, `retry_after_s`; an `offline` error is a frozen run's cache miss (a skip, never degraded); a `refused` fetch (SSRF, robots.txt, the paywalled-publisher list) is the gate working, not a broken source. Every adapter is built `Class(store=store)` (the MCP server does this) or `Class(client=client)`; built from a store alone it uses `SourceClient.for_store(store)`, one client per store, so request spacing holds across adapters and tool calls. `build_sources(config, *, store, mode)` returns a `SourceSet(client, search, text, expand, crossref)`; `SourceConfig` holds every secret and address as an explicit field (`mailto`, `openalex_api_key`, `semantic_scholar_api_key`, `searxng_url`, `tdm_allowed_hosts`, `scholarly`, `arxiv_query`, `expand_with`, `openalex_search`, `arxiv_pdf_interval_s`). `arxiv_query` (`all_terms`, the default, or `any_term`) joins the words of an arXiv query by AND or OR; `expand_with` (`None`: every source that has citation links, as before) limits which sources `SourceSet.expand` holds, so a source can be searched and read without being asked for citation hops.

- **`SourceClient`** (`base.py`): `get` / `get_json` read the store cache first (key = source + URL + `params`; `auth_params` and `headers` are sent but never keyed or stored, so a key is not written into the cache and one answer serves every caller), space network requests per source (a slot is reserved under a short lock and waited for outside it: starts stay `interval` apart while requests overlap in flight, at most `DEFAULT_INFLIGHT` at once: Crossref 3, OpenAlex 4, Europe PMC 2, every other source and each fetched host 1), retry 429/500/502/503/504 (`DEFAULT_RETRIES` 2; the wait is `Retry-After` or 1 s, 2 s; a wait over `MAX_RETRY_WAIT_S` raises at once instead of sleeping), cache only a 200 and only after the adapter's `validate` accepted it (Europe PMC, arXiv and SearxNG answer some failures with a 200 body; none is remembered for a week). It reads `x-ratelimit-*` and `Retry-After` into `rate_info[source]`, adds `x-ratelimit-cost-usd` to `spent_usd[source]`, and once a server says `remaining` is 0 with a reset further than the retry cap it refuses further calls locally (`rate_limited`) rather than hammering it. `fetch_document` is for URLs from the open web or a record: `check_fetch_allowed` (robots.txt, paywall list, `tdm_allowed_hosts`), `fetch_with_safe_redirects` (SSRF on every hop, size cap), `deep_research.content_extractor.extract_content` (harvest), at least `MIN_FULL_TEXT_CHARS` of text, cached as text for `TTL_FULL_TEXT_S`. `get` never follows redirects (API hosts are fixed). `fetched_bytes` and `requests` feed `RunStats`; the `extractor`, `clock` and `sleep` are injectable, so the tests run no network and wait for nothing. **One limiter per source for the process**: a client built on the real clock inside a running loop takes `sources.process_pacing()` (one `SharedPacing` per event loop: request locks, last-start times, in-flight semaphores and the "budget is spent until" marks), so concurrent items, live arms and the freeze's own clients space requests to one source or fetched host as one client would (`DEFAULT_INTERVAL_S`: arXiv 3 s, Semantic Scholar 1 s, Europe PMC 0.2 s, OpenAlex and Crossref 0.1 s; arXiv PDFs 15 s) and a source that said its budget is spent is refused locally by all of them. A client with an injected `clock` or `sleep` (a test double) keeps a private pacing, as does one built outside a loop; pass `pacing=` to choose. `SourceClient(store, offline=True)` (no `client` may be passed) never touches the network: `get` and `fetch_document` answer from the cache at any age (`store.cache_get(any_age=True)`) or raise `kind='offline'`, its `http` has a transport that refuses every request with a `ConnectError` (so Crossref through `references` and the link checks reach nothing either), and every miss is counted in `offline_misses` (by source, or by host for `http`). `client.reference_cache()` is the store's `references` cache with the same any-age rule.
- **PDF extraction** (`extraction.py`, `SourceConfig.pdf_extraction` / `SourceClient(pdf_extraction=...)`): `docling` (the library default, unchanged: harvest's docling pipeline, layout-aware, seconds to minutes a paper and gigabytes of memory) or `fast` (the PDF's text layer through pypdfium2: milliseconds, no layout, no OCR; a scan has no text layer and raises `ExtractionError`, so the reader falls back to the abstract; line-end hyphens are joined, paragraphs end at a sentence on a short line). The bench CLI defaults to `fast` (`--pdf-extraction`). Only PDFs differ; HTML goes through harvest either way. `SourceClient(patient=("semantic_scholar",))` gives the named sources the patient schedule (a freeze asks a shared, rate-limited pool): 8 retries waiting `PATIENT_RETRY_WAITS_S` (5, 10, 20, 40, 60, 60, 60, 60 s), a longer `Retry-After` honoured up to `PATIENT_MAX_RETRY_AFTER_S` (120 s), and after `PATIENT_GIVE_UP_AFTER` (3) requests in a row that ran out of retries the source is refused (`rate_limited`, nothing sent) for the rest of the process (the count and the refusal live in `SharedPacing`, so every client of the process shares them; a success resets the count; a cached answer is still served). Live runs and every other source keep `DEFAULT_RETRIES`. `SourceClient.extractions` maps each fetched URL to the extractor used (`pypdfium2`, `docling`, `harvest-html`, `text`, `custom`).
- **OpenAlex** (`openalex.py`): keyword search is `search.title_abstract_keywords` (stemmed, boolean allowed) with cursor paging (`cursor=*`, `meta.next_cursor`, `per_page` up to 100); `search.semantic` is a separate call (`search_semantic`, or `mode='semantic'|'both'`), one page of at most `SEMANTIC_MAX` (50). References: the work's `referenced_works` (free lookup by `/works/doi:...`, `pmid:`, `pmcid:`, then batches `filter=openalex:W1|W2` of 50); citations: `filter=cites:W...&sort=cited_by_count:desc`. Abstracts arrive as an inverted index and are rebuilt. Text is the work's `open_access.oa_url` through `fetch_document`.
- **Europe PMC** (`europepmc.py`, `jats.py`): `search` with `resultType=core`, cursor paging; filters become `PUB_YEAR:[a TO b]` and `OPEN_ACCESS:y` terms. References/citations from `/{MED|PMC}/{id}/references|citations` (entries have title, authors, year, ids, no abstract); a work with only a DOI is located by a `DOI:"..."` search first. Full text is `/{PMCID}/fullTextXML` read by `jats_to_text` (title, abstract, sections and paragraphs as markdown; formulas, tables, figures and the reference list left out; parsed with `_util.parse_xml`, which resolves no entity and loads no DTD). A 404 is "not in the open-access subset" (`None`).
- **arXiv** (`arxiv.py`): Atom API, `to_search_query(query, *, form)` turns a plain query into up to 8 significant words (3+ letters, stop words out, each once) over `all:` joined by AND (`all_terms`, the default: a long query often finds one work or none) or by OR (`any_term`: ranked by the relevance sort, never empty; same words, same `sortBy=relevance`, same 20 results) (field syntax is passed through; the cache key carries `search_query`, so the two forms never share a row), 3 s between API calls. The PDF comes from `arxiv.org/pdf/<id>` at a 15 s spacing (`ARXIV_PDF_INTERVAL_S`, arxiv.org's robots.txt crawl delay; `export.arxiv.org`, the API host, disallows robots entirely, so PDFs cannot come from it). A year filter is applied after the fetch. Error entries in a 200 feed raise.
- **Semantic Scholar** (`semantic_scholar.py`): optional; `x-api-key` header from `api_key`; no key works but shares a pool and often gets 429 (raised as `rate_limited`; round 3 uses it keyless, for search only, through the patient schedule below). Every work and every cache row is tagged `no_redistribute`. A reference list the publisher withheld comes back `data: null`: an empty list, not an error.
- **Crossref** (`crossref.py`): no client of its own; `references.ReferenceHttp` (sharing the store cache through `store.reference_cache()`) and `lookup_retraction`. `search`, `get_work(doi)`, `retraction_status(doi)` (`retracted` > `concern` > `correction` > `no`; `unknown` for a DOI Crossref lacks; a failed call raises, never reads as `no`). Not in the default scholarly list: it verifies, it does not discover.
- **Web** (`web.py`): SearxNG JSON search (explicit `searxng_url`, no default), up to 3 pages, deduplicated by canonical URL; no results while engines were unresponsive raises and is not cached. All SearxNG queries (this adapter and the legacy backend) go through `deep_research/searxng_search.py`: spaced `SEARXNG_MIN_INTERVAL_S` (1.5 s) apart by the client's `DEFAULT_INTERVAL_S["web"]` (the process-wide `SharedPacing`, no second limiter); a blocked reply whose every engine names a rate-limit or CAPTCHA reason is retried after 5, 15 s (`SEARXNG_RETRIES` 3 attempts, `SEARXNG_RETRY_DELAYS_S`) then raises `SourceError(kind='rate_limited')`; some results with an engine down come back with a warning that `steps.search` records in `ResearchResult.notes` (`WebSource.take_warnings`), not as degraded. Search goes through the shared client, not `backends.HttpxSearchBackend`, because it must be cached and must raise; the fetch reuses the same gate, SSRF layer and extractor but not the backend's 50,000-character cap.
- PubMed and Unpaywall are not adapters: Europe PMC indexes PubMed, OpenAlex carries the open-access locations.

### Verified against the live services (2026-10-05)

- OpenAlex has changed since the older docs: pagination is `page`/`per_page` or `cursor`; the cost is in the response (`meta.cost_usd`) and in headers `x-ratelimit-cost-usd`, `-credits-used`, `-limit`, `-remaining`, `-reset` (seconds), `-remaining-usd`, `Retry-After`. A keyless caller has 1000 credits a day (a search or semantic search costs 10, a filtered list such as `cites:` or `openalex:` 1, a single-work lookup 0); a free key raises it tenfold. `search=` now means full-text search; the adapter uses `search.title_abstract_keywords`. `search.semantic` exists, cannot be combined with another search, takes about nine seconds and returned 504 `query_timeout` on three of five calls (with no charge): a failure is raised and recorded, and the default mode is keyword. `mailto` is still accepted.
- Europe PMC: `https://www.ebi.ac.uk/europepmc/webservices/rest/search` (`query`, `format=json`, `resultType=core`, `pageSize`, `cursorMark`/`nextCursorMark`); core records nest `authorList.author[]`, `journalInfo.journal.title`, `fullTextUrlList.fullTextUrl[]`, `pubTypeList.pubType[]`; `/{PMCID}/fullTextXML` gives JATS 1.4 with a DOCTYPE; `/{source}/{id}/references` and `/citations` give `referenceList.reference[]` / `citationList.citation[]`. No rate limit is documented.
- arXiv: `https://export.arxiv.org/api/query`, Atom 1.0 (`entry/id` with a version, `title`, `summary`, `author/name`, `published`, `arxiv:doi`, `arxiv:journal_ref`); max 2000 results a request; ToU asks for one request in three seconds; the pages and PDFs of `arxiv.org` carry `Crawl-delay: 15` and allow `/pdf`.
- Semantic Scholar: the Graph API shape (`paperId`, `externalIds`, `openAccessPdf`, `data[].citedPaper|citingPaper`) is from the docs and a recorded reference response; the keyless search answered 429 at once, so the search fixture is synthetic in the documented shape.
- A live smoke run of every adapter (OpenAlex search, references and citations; Europe PMC search and full text; arXiv search; Crossref lookup and retraction) returned sensible works; it is not part of the test suite.

Tests: `tests/test_sources_*.py` with `tests/source_stub.py` (a mock transport, fake clock and sleep) and recorded or synthetic fixtures in `tests/fixtures/` (OpenAlex, Europe PMC and arXiv responses trimmed to two records each; the JATS, Semantic Scholar, Crossref and SearxNG files are invented).

## The engine (`graph.py`, `steps.py`, spec §5)

```
Plan -> Search -> Screen -> Expand -> Screen -> Read -> Coverage
    Screen -> Read           web mode, no expanding source, or the round's expansion done
    Coverage -> Search       a sub-question is still open: the next round
    Coverage -> Write        covered, unresolvable, a spent budget, flat, max_rounds
Write -> Verify -> Finish
```

- **Thin nodes, engine-free workers.** Nodes route and assign `ResearchState`; `steps.py` and the worker modules compute and return values (the dialect check passes; `steps.py` never imports `pydantic_graph`). `ResearchDeps` (frozen) carries the question, mode, store, `SourceSet`, the run's `Asker` and `Screener`, `ReadDeps`, a `ReferenceHttp` for verification, the budget and the clock. `tests/test_graph.py::test_the_topology_is_the_specified_one` pins the edges above.
- **The configuration** decides each swappable step (see "Configuration"); the descriptions below are the steps' mechanics, and name which preset a rule belongs to where they differ.
- **Plan**: one LLM call (none with frozen inputs), 2–6 sub-questions (`steps.plan`; flat schema, a validator re-asks on a count outside 2–6, an empty or repeated one). With a decision model each sub-question's kind is a `choice` (`KIND_QUESTION`, step `plan_kind`). A metadata sub-question's years and open-access wish become `SearchFilters` by code (`steps.filters_for`: "since 2020", "after 2019" = from 2020, "before 2015" = to 2014, "2018-2022", "between X and Y", "in 2021", "open access"). Then, when the configuration uses criteria, the rubric of every sub-question (`steps.compile_all`, `Screener.compile`).
- **Search**: one LLM call per round writes up to `queries_per_subq` keyword queries for every open sub-question (`steps.write_queries`): never a query already run (case and spacing folded), aimed at the coverage gaps (`steps.coverage_gaps`); a sub-question that gets no new query is searched by its own text once. Every query runs on every source of the mode, one call after another (`steps.search`), and the results are merged by identity, stored (`steps.admit`: `store.upsert_work`, then `identity.merge_pair` with a candidate the run already has) and become `(work_id, subquestion_id)` pairs waiting for screening.
- **Screen**: at most `candidates_per_round` waiting pairs (offered in the order the configuration's `queue` strategy gives: arrival order, or best source rank first), a fair share of each sub-question and at most `screen_per_subquestion` of one (`steps.round_robin`), through `strategies.screen_one` (the screen strategy, then the refine strategy, ranked by `criteria.rank`; with `criteria` + `on` this is exactly `Screener.screen`). The rubric that stands after refinement replaces the old one (a generic screen leaves none). Pairs over the cap, or whose scorer failed, stay waiting for the next round. A pair kept for the first time counts as a new kept candidate of the round.
- **Expand** (scholarly and both, once per round, unless the expand strategy is `off`): the `expand_seeds` best kept works (by the rank strategy) with a scholarly identifier, not expanded before; references then citations from every expanding source, `EXPAND_PER_CALL` (20) a call, until `min(config.expand_per_round, Budget.expand_per_round)` candidates. Each new candidate's place in the hop's list is its `source_ranks` entry. A new candidate inherits its seed's sub-questions and goes back through Screen. A source that cannot place a work (`kind='config'`) is a note, not degraded.
- **Read**: at most `read_per_round` works (a `Budget` field added for the engine; 20), kept pairs not read yet, within `read_per_subquestion` over the run, works of uncovered sub-questions first, then by the rank strategy's value (`steps.read_targets`), through `read.read_works` with the passage strategy as `ReadDeps.select` and `passages_per_work` from the configuration. Retracted works land in `excluded` and are never read.
- **Coverage**: `compute_coverage` over every finding and candidate score, recorded each round. `decide_stop` decides. Conflicts are judged once, when the search stops (pairs are judged once anyway; they do not change routing).
- **Write / Verify / Finish**: `write_report`, then `verify_report` (the report is replaced by the marked one), then the result: `works` are the cited works in order of first citation, then the other kept works by best score, never an excluded one; `excluded` maps each left-out work to its reason; `degraded` is the de-duplicated list of every failure; `stats` are this run's (cache hits and misses, fetched bytes and requests per source are counted from the store's and client's values at the start, so a shared store or client reports the run alone).
- **Budget**, every bound a stop reason, never an exception: rounds (`max_rounds`), model calls (`max_llm_calls`, `max_decision_calls`, counted in `Asker`), the clock (`max_wall_s`, measured on the injected `clock`, checked at every node), fetched bytes (`max_fetch_bytes`, read through `ReadDeps.fetched_bytes`). The search stops early enough to write: when no more than `steps.write_reserve` language-model calls are left (2 + 1 per sub-question), the bound counts as spent (`budget:max_llm_calls`). A writer that still runs out lists its section's claims (see WRITE). `decide_stop` ranks a spent bound above a flat curve, because a round the budget cut short keeps few candidates for that reason.
- **Failures** follow one rule in every step: a `SourceError` is recorded in `degraded` and the other sources go on (a dead SearxNG in mode `both` leaves a degraded run with scholarly findings, never an empty one); a model failure is one of `ask.MODEL_ERRORS` (pydantic-ai's `AgentRunError`, `core.decisions.DecisionError`, `ask.AskError`, of which `CriteriaError` and `ScreeningError` are subclasses), recorded, and the step falls back to a plainer path that invents nothing: the question as its one sub-question, one relevance criterion (`steps.fallback_criteria`), the sub-question as its own query, unscreened pairs left waiting, an unread work left for a later round, conflicts and claim support left unjudged and said so. Anything else is a bug and raises; `research()` records the run as failed (`finish_run` with the reason) and re-raises.
- **`research()`** owns what it opens: a store from a path or `None` (in memory) is closed at the end, a store passed open is not; a decision model given by name is opened (`DecisionModel.open`) and closed, a handle is used as given; a `SourceClient` is built for the store unless one is passed (it must belong to the same store). `model` is a pydantic-ai id or `Model` object. Secrets in `SourceConfig` are left out of the run's recorded config.
- **CLI** (`cli.py`): `--preset` names the configuration (default `baseline`; the summary line on stderr names it and its hash); every `Budget` field is a flag (`--max-rounds`, `--read-per-round`, ...); secrets come from the environment after `load_dotenv()` in the CLI only (`OPENALEX_API_KEY`, `OPENALEX_EMAIL`, `SEMANTIC_SCHOLAR_API_KEY`); progress lines go to stderr (`--quiet` silences them). Exit 0 clean, 4 finished but degraded (result written, reasons on stderr), 1 error, 2 usage.
- **Tests** (`tests/test_graph.py`, `tests/test_steps.py`, `tests/test_cli.py`; `tests/test_presets.py`, `tests/test_strategies.py`, `tests/test_frozen.py` for the configuration and frozen inputs; the scholarly end-to-end test runs both presets): the whole engine runs offline over `tests/engine_world.py`, an invented world (two topics, six works in OpenAlex's shape, one retracted in Crossref, one found only as a citation, four web pages behind SearxNG) answered by a mock transport, a `ScriptedLLM` that answers each prompt by reading it, and a `StubDecisions` decision model. Every mode, both scorers, the retraction, a dead source, the budget stops and a second run reading the first one's cache are covered. Patch `andamentum.references.http.is_safe_url` and `core.url_safety.is_safe_url` and clear `fetch_gate`'s robots cache: the world's hosts are invented.
- **Not yet measured live**: no run against real sources and models has been made in this build; the numbers above are design bounds, not measurements.

## MCP server

`mcp_server.py` — `andamentum-research mcp [--store PATH] [--model M] [--decision-model NAME] [--searxng-url URL]` (stdio; `cli.main` dispatches it before argparse, like `agents` and `v2`). Without `--store` the store lives in memory. Secrets as for the CLI. Tools, every one writing only to the store:

- `search_works` (sources from `openalex`, `europepmc`, `arxiv`, `semantic_scholar`; each source's failure reported, all failing is an error), `search_web` (needs `--searxng-url`), `expand_citations` (`openalex`, `europepmc` or `semantic_scholar`): adapters from `build_sources` over the server's one `SourceClient`, so spacing and the cache hold across calls; duplicates merged, works stored.
- `read_work`: the stored work and its passages; `fetch` runs `read.load_work` (retraction check, text, passages; no model); `subquestion` with `run_id` runs `read.read_work` (selection, extraction, quotes checked in code) and records the findings in the run, numbered after the run's last finding.
- `screen`: starts or reuses a run, records the sub-question with the next free id (two screens in one run never overwrite each other), compiles the criteria with `Screener.compile` when none are given (needs `--model`), scores with `Screener.score_candidates` through an `Asker` over the server's store, so every answer lands in `decisions` and every decision in `run_items`.
- `record_finding`: the quote must be in a stored passage of the work (`read.locate_quote`: exact, then folded); the stored quote is the passage's own words. The abstract becomes a passage only when the work's licence allows its use (`Work.redistributable`).
- `get_run`, resources `research://run/<run_id>`, and `research` (the whole engine against the server's own store and client; needs `--model`).

The decision model is opened once, at the first call that needs it, and closed when the server stops; model-calling tools hold one lock, so a local model sees one request at a time. `tests/test_mcp_server.py` drives the real modules through the SDK's in-memory client over `engine_world`.

## Read, coverage, verify, write (`ask.py`, `read.py`, `coverage.py`, `verify.py`, `write.py`, spec §5-6)

- **`ask.Asker`** is the one place the run's models are called. `ask.MODEL_ERRORS` names what a failed model call raises; every caller catches exactly that tuple. `llm(...)` is a counted, budget-checked structured call. `ask_each(step, instruction=, states=)` is a yes/no question over many states: the decision model gets one `noul` request per state (each answer logged to `decisions`); without it the language model answers batches of 8 and each probability is 1.0 or 0.0, none invented. A spent bound raises `BudgetExhausted(name)`; workers that loop catch it and report `stopped`, they never hide it. Language-model calls run one after another for every model.
- **READ** (`read_works`, `read_work`, and `load_work` for steps 1-3 alone, no model; the MCP `read_work(fetch)` uses it). Order per work: Crossref retraction check (`CrossrefSource.retraction_status` from `ReadDeps.crossref`, so the notice mapping and the request spacing are the adapter's; a retracted work is excluded and never read; a failed check is a `degraded` note, never "fine") -> text from the first `TextSource` that holds it (the caller orders them; sources cache what they fetch, so nothing is fetched or extracted twice; a refusal is a note, any other `SourceError` also degrades) -> passages (~1,200 chars, paragraph boundaries, exact slices, content-addressed, stored) -> selection (decision model: `Screener.score_passages` + `criteria.select_passages`; otherwise one batched language-model pick; a word-overlap pre-filter caps what a model looks at: 60 for the decision model, 20 for the language model) -> flat extraction `{passage, claim, quote, criteria}` -> **quote check in code** (`locate_quote`: exact, then case, whitespace, quote-mark and dash folded, NFKC; the stored quote is the passage's own text at the matched span; under 20 characters is refused). A finding whose quote is nowhere in the selected passages is dropped and recorded as a `quote_missing` flag item. A work under a `no_redistribute` licence is never read from an abstract. `access` is written back to the work. `skip` takes the `(work_id, subquestion_id)` pairs of earlier rounds (`ReadOutcome.done`). `ReadDeps.fetched_bytes` (e.g. `lambda: client.fetched_bytes`) lets the `max_fetch_bytes` bound see what the source client has fetched. A model that fails on one work is recorded on that work's reading as degraded and `read_works` goes on; the work is not marked done, so a later round may try again. A dropped quote's record says whether it was missing or too short.
- **COVERAGE** (`compute_coverage`, `decide_stop`, `find_conflicts`, `record_coverage`). Independence is by *origin*: family name of the first author, else registrable domain of the URL, else the work. A preprint and its journal version, or two papers by one first author, count once. `covered` = >= 2 independent sources (the spec's rule); `per_criterion` counts independent sources for each `must` criterion (passage criteria: findings that name it; candidate criteria: candidate scores with p >= 0.5) and the `note` names the ones at zero, which is where a further search should aim. `unresolvable` = not covered after 2 rounds and fewer than `MIN_NEW_PER_ROUND` (3) new kept candidates for it in the last round. `decide_stop` is pure: covered, unresolvable, `budget:<name>` for a bound the caller found spent, flat (last round under the minimum, from round 2), then `budget:max_rounds`. Conflicts: pairs of findings of one sub-question from *different origins*, most alike first, capped at 40 pairs per sub-question over the run (`checked` is the run's memory; a pair is judged once); the decision model answers a `noul` "do these contradict", else the language model in batches.
- **VERIFY** (`verify_report`). Sentences are the stretches that end at a `[F12]` citation (so `[F1][F2]` is one sentence). Headings and everything from `## Sources` on are not sentences; the fixed lines the writer builds in code (`write.CODE_LINE_PREFIXES`) carry no ids by design. Checks: quote in passage for every finding; cited ids exist; claim support per sentence (flag `unsupported`, sentence marked ` [unsupported]` in the returned report; a sentence citing nothing is `unsupported` too); retracted work cited; single-source sentences; links and DOIs (Crossref, then doi.org for DOIs Crossref does not hold, e.g. DataCite). Only a settled "not there" (404/410, unresolvable host, refused address) is a `dead_link`; timeouts, 5xx and bot blocks (401/403/429) land in `unchecked`. A spent budget is reported in `degraded`, never treated as support. Every flag is written to the run's items. A sentence rests on its *own* citations: one finding per sentence is normal, so `single_source` flags are common and mean "this sentence has one independent source".
- **WRITE** (`write_report`). One language-model call per sub-question, flat `{text, finding_ids}` sentences; code appends `[F..]` (ids the model wrote into the text are stripped), and an id that is not one of the section's findings is sent back through the validator. Everything else is built in code: title, sections, the fixed no-evidence and limited-evidence lines, `## Disagreements` from the two claims of each conflict, `## Sources` with the link of each cited work. Findings of retracted works are never offered to the model. At most 30 findings per section, one origin at a time. A section the writer cannot write (budget spent, model failed) lists its findings' own claims, each with its id, and `Report.degraded` says so: still cited, still verified, never invented.
- Test helpers: `tests/llm_stub.py` (`ScriptedLLM` over pydantic-ai `FunctionModel`, `decisions(...)` over `StubDecisions`, `http(...)`, `make_asker(...)`).

## Benchmark (`bench/`, spec §9)

Run with `uv run python -m andamentum.deep_research.v2.bench --help`: `download litsearch|synergy --dir DIR`, `verify-web-set`, `web`, `litsearch`, `screening`, `report FILE.json ...`, `cache import --cache PATH SRC...` (merge the HTTP caches of existing store files, or of every `*.db` under a folder, into the shared cache; prints rows imported, expired, older and unreadable per source). Every directory is named on the command line (no default location); runs are sequential and write `<task>-<arm>.json` into `--out-dir` after every item; the exit status is 2 when any item failed (the error is in the file, and the item counts against the arm: a wrong answer, recall 0). Tests use tiny invented data and stub models; the two tests that touch the network carry `research_eval` (deselected; `uv run pytest -m research_eval`).

- **Concurrency** (`bench/concurrency.py`, `--concurrency N` on `freeze` and `experiment run`, 1 to 4): more than 1 only when every language model is an Ollama `-cloud` model (`is_cloud_model`: `ollama:` prefix and a `-cloud` name; decision of 2026-10-06, cap `MAX_CLOUD_CONCURRENCY` 4); a local model is refused with a `ValueError` naming it, never lowered silently, before anything runs. Freeze runs items concurrently; an experiment runs the cells of one arm concurrently (arms stay in sequence, each cell has its own working store copy). Decision-model requests are serialised per server by `core.decisions`' lock whatever the value (`tests/test_bench_speed.py` pins that concurrent items never overlap requests). The registry's `start` line and the experiment report state the concurrency used; wall times are measured under that load. `run_bounded` starts no job after one fails.
- **Data and licences** (checked 2026-10-05, written into `MANIFEST.json` beside the data with sha256s). *LitSearch*: the code repository is MIT; the Hugging Face dataset card declares no licence of its own. The 597 queries come from the dataset-viewer JSON API (the 1.2 GB parquet corpus and a parquet reader are not needed); the gold papers are Semantic Scholar corpus ids, resolved to title and identifiers by the Semantic Scholar batch endpoint (the viewer's `/filter` answers 500 on this corpus). That metadata stays in the data directory, never committed or redistributed. *SYNERGY v1.0* (screening): CC0-1.0, from the `v1.0` tag of `asreview/synergy-dataset` through `raw.githubusercontent.com`, one review at a time (the DataverseNL copy sits behind a bot wall that refuses scripted downloads). The review's published title is the question the screening arms are asked.
- **Subsets** are `select_subset`: `sha256(seed:id)` order, so the same ids and seed give the same sample anywhere, and a larger `n` extends a smaller one. Screening samples are stratified by label (`sample_records`): the review's prevalence is kept (at least 10 included records, or all there are), so work saved on a subset compares with the full review's. The subset size and seed are in every results file.
- **Web set** (`web_set.py`): 15 questions written for this benchmark, answers that Wikipedia or the RFC editor states; correctness is a deterministic whole-word check (every group of `all_of`, any phrase of a group), lenient on purpose (no negation reading). `verify-web-set` fetches each source page and checks it still states the answer (a drift check). It uses `urllib`: Wikipedia answers `httpx` with 403 and the standard library with 200 from the same machine and headers.
- **Metrics** (`metrics.py`, pure): recall@k and kept-set precision (gold is sparse, so the precision is small by construction); screening kept recall and precision and work saved at 95% recall from the ranking, where tied scores are read together (an LLM scorer that answers only yes or no gets no credit for ties); claim-support precision over judged claims only, with `unsourced` claims reported beside it (an uncited report sentence; a legacy evidence item whose page was never fetched); URL integrity as ok / (ok + dead) with unverifiable links (bot-blocked 4xx, timeouts) counted neither way, capped at 25 links an answer.
- **Arms**. Web and LitSearch: `legacy` (`run_research`, web only, its pages matched to gold by title containment) and `v2` (`research()` with `store=None`, so every question pays for its own searches; the decision model is the one handle the bench CLI opens for both arms). `tests/test_bench_arms.py` runs the v2 arm against the real engine over `engine_world`. Screening: `generic` (one `must` question) against `criteria` (the compiled rubric), each with the `decision` model or the `llm` as scorer, through the engine's own `Screener.score_candidates` and `combine`, so the arms differ only in the criteria list and the scorer. The rubric is compiled once per review and shared; its LLM cost is part of each criteria arm's cost. Refinement is not benchmarked. The claim judge is its own model (`--judge-model` or `--judge-decision-model`), never the engine's: a decision model that both writes and grades `claim_supported` grades itself.
- **Secrets** come from the environment in the CLI only, after `load_dotenv()`: `SEMANTIC_SCHOLAR_API_KEY`, `OPENALEX_API_KEY`, `OPENALEX_EMAIL`.

## Novelty check (`novelty.py`)

`run_novelty_check_v2(claim, *, model, decision_model, store=None, sources=SourceConfig(), budget=NOVELTY_BUDGET, source_client=None, progress=None) -> NoveltyReport` (the legacy `novelty.models` report) is the v2 path of the novelty check; whetstone's `--novelty-engine v2` calls it. `decision_model` is required (a name, opened and closed here, or an opened handle). One scholarly `research()` run (the default `baseline` preset, so the passages are the BM25 selection), then for every passage of a kept work (a retracted work is never evidence) one decision request with two `noul` questions (`anticipates`, `related`), logged under step `novelty` in `decisions`. The verdict (`_verdict`, pure) is a function of the answers and the run's health:

- a passage with `anticipates >= ANTICIPATES_AT` (0.5): `is_novel=False`, confidence the highest p; `similar_work` has one entry per work with the best passage's own words as the summary (`direct` from `DIRECT_AT` 0.8); a degraded or budget-stopped search does not weaken this (positive evidence);
- no anticipating passage and the search healthy (no `degraded`, no `budget:` stop, the decision budget not run out, at least `MIN_WORKS_ASSESSED` (3) works read): `is_novel=True`, confidence `1 - max p`;
- otherwise `is_novel=None` with the reasons named in the assessment, which is also what a decision-model or language-model failure (`MODEL_ERRORS`) gives. Anything else raises.

`NoveltyResearch(decision_model, sources, store, budget)` is the setup a caller (whetstone) hands around. `ResearchResult.queries` (added for this) lists the searches that were run. The two thresholds and the minimum are not calibrated; nobody has measured the precision of `anticipates`. Tests: `tests/test_novelty.py` over `engine_world` (a stub decision model that judges by passage text) plus the verdict rule on hand-built results.

## Round-2 measurements and the decision cache

- **Per-step timing and calls**: `RunStats.step_seconds`, `step_llm_calls`, `step_decision_calls` (steps `types.STEPS`: Plan, Search, Screen, Expand, Read, Coverage, Write, Verify; a step never reached has no entry). `graph._timed(ctx, step)` wraps each node's body: it sets `Asker.phase`, which `Asker.llm` and `Asker.decide` count under, and adds the seconds on the run's clock (a node visited twice, like Screen, accumulates). The sums equal `llm_calls` and `decision_calls`. They reach the store with the run (`runs.stats_json`) and the bench registry (inside each record's `output.result.stats`), and `bench experiment report` tabulates them.
- **Decision cache** (`research(decision_cache=True)`, every preset; `ask.Asker.decision_cache`, `decision_cache.py`, schema version 3): `Asker.decide` serves an answer from the store's `decision_cache` table when the same model digest, request (`ask.request_key`: each question's `question_hash` under its key) and state hash answered before; a hit counts in `stats.decision_cache_hits`, not in `decision_calls` (it needs no budget), and is still logged in `decisions` with `ms` 0. Before a run uses it, `check_determinism` sends one fixed request twice; identical answers enable the cache, different ones (or a model with no digest, or a failed check) disable it for that run: `stats.decision_cache` says `disabled: <why>`, a note says so, and a `check` run item `decision_determinism` records it. The verdict is kept per digest in the store (`decision_determinism`), so a store that judged a model does not probe again; the probe's two requests are `stats.decision_probe_calls`, not `decision_calls`. Without a decision model it does nothing (`decision_cache` is `off`). `frozen.capture` builds its own asker and never caches.
- **Shared decision cache** (`research(shared_decisions=store)`, `Asker.shared_decisions`, `--decision-cache PATH` on `bench experiment run`; allowed with `frozen=`): a second store the decision cache reads through to on an own miss (the answer is copied into the run's own store) and writes every answer to as well; the determinism verdict per digest is read from it too (`check_determinism(shared=)`, so the probe's two requests are made once per model for every run that shares it). A hit counts in `decision_cache_hits` and in `RunStats.decision_shared_hits`. It changes what a run costs, never what it finds: a cached answer is the answer a request would get, which is why a model that fails the determinism check gets no cache at all, shared or own. Reports state "decision answers" = `decision_calls` + `decision_cache_hits`, so the order of the arms cannot flatter a cost. The solo (clean-timing) cells never use it.
- **Degraded threshold**: a text source that fails on one work (not a routine refusal) is a `WorkReading.failed_notes` entry and a note of the run, no longer `degraded`. A run is degraded for unreadable works only when more than `read.UNREADABLE_DEGRADE_SHARE` (0.5) of the works chosen for reading (not excluded) ended with access `unreadable` (`read.unreadable_degraded`, applied in `Finish`). Search errors, a failed model and a failed retraction check stay `degraded` as before.

## Benchmark additions for round 2 (`bench/`)

- **Experiment file** (`experiment.py`): `Rule.test: reduced_by` (per item `1 - arm/reference`, items with a zero reference drop out, aggregated by `aggregate`, accepted when the aggregate itself is at or above `threshold`; the interval is reported, not tested); `aggregate: max` (the largest item value, exact: `at_most 0` on it reads "no item"); `Rule.also_sets` pools more sets into a rule's values (items named `<set>/<item>`); `Rule.group` names rules that stand or fall together and `Experiment.decisions` (`id`, `requires` groups, `if_accepted`, `otherwise`) fixes in the file the wording of what the groups decide. `ArmSpec.solo: N` (clean timing: the first N items of each set, after every other arm, always one cell at a time) and `ArmSpec.outage: record` (a live arm whose cell fails, by a search outage or any other error, is recorded as failed: `RunRecord.outage`, an error text, no metrics at all, so it is neither a zero nor a pairing partner; default `stop` keeps round 1's behaviour). SearxNG is probed before every cell of the legacy arm (it searches the web for any set).
- **Report**: solo arms stay out of the ordinary tables; extra sections for per-step seconds and requests, claim checks by code vs model and cache state, failed runs (outages apart from other errors), clean timing, the rule groups' outcomes and the decisions' wording. `web_planted` errors no longer count as "did not adopt the false claim" (`adopted_false_claim` is absent for a crashed cell, so a gate that reads it is inconclusive instead of passing).
- `bench/experiments/round2.yaml` is the registered experiment (arms, rules R1-R6, wording); the letter-to-arm mapping is in its header.

## Round 3: raising LitSearch recall (`bench/experiments/round3.yaml`, `bench/pool.py`)

The round-3 diagnosis (on the 28 LitSearch items of round 2: 24 of 31 gold papers lost, 22 of them never in the candidate pool; the arXiv adapter ANDed every query word; Europe PMC supplied 72% of the candidates and no gold paper, and took the first screening slots) led to three options, each defaulting to what the engine did before, so the baseline's hash and recorded trace did not move: merit-ordered screening admission (the `recall` preset, see Configuration), the any-term arXiv query (`SourceConfig.arxiv_query`) and keyless Semantic Scholar search (`semantic_scholar` among the scholarly sources, `expand_with=("europepmc",)` so no citation hop is asked of it). `round3.yaml` registers the test: arms `v2-baseline`, `v2-arxiv` (recall preset + any-term arXiv), `v2-combined` (+ Semantic Scholar) and `v2-combined-solo`, all on the same sub-questions and queries (written once for the `r3-base` profile), 32 fresh LitSearch items (`litsearch {n: 32, skip: 28}`: positions 29-60 of the seed-0 order) and the 15 web questions, with rules P1 (the primary: recall@20 of `v2-combined` above `v2-baseline`, paired, the whole interval above 0), L1, L2, H1 (at most 10% failed searches), guards G1-G3 (`no_harm`) and T1, and the decisions that follow. The numbers are not measured yet: this build ends before the freezes.

- **Inputs profiles** (`experiment.InputsSpec`; `Experiment.inputs`, `ArmSpec.inputs`): a profile fixes `sources` (the `SourceConfig` fields `scholarly`, `arxiv_query`, `expand_with`, `results_per_query`), `plan` (`live`, or the name of the profile whose sub-questions and queries are reused), `prefetch_top_k`, `patient` (sources asked with the patient schedule) or `existing: true` (snapshots taken by an earlier experiment, used as they are). A frozen arm names the profile of every set it runs; its snapshots are `<snapshots>/<profile>/<set>/<item>/` (a `web_planted` item reads the plain `web` snapshot of its profile) and its run-time `SourceConfig` is the run's own updated with the profile's `sources`, so its offline text sources and citation expansion match its freeze (`experiment_run.profile_sources`, `snapshot_root`). The profile's canonical-JSON hash is in every snapshot's `meta.json` and in the registry's `start` line (`StartRecord.inputs`, `ArmRecord.inputs`, `StartRecord.keyless`). `Experiment.config_hash` leaves the new fields (`inputs`, `keyless`, a set's `skip`, an arm's `inputs`) out while they hold their defaults, so round 1 and 2's files keep their recorded hashes (`test_the_files_of_rounds_one_and_two_keep_their_hashes`).
- **Freezing a profile**: `bench freeze litsearch --experiment FILE --inputs PROFILE --snapshots DIR --dir DATA [--cache PATH --concurrency N]`. The items are the experiment's set (its `n`, `skip`, `seed`); the sources, prefetch depth and patience come from the profile. A profile whose plan is another profile's reads that profile's `<snapshots>/<plan>/<set>/<item>/frozen.json` and needs no `--model` and opens no decision model; `--plan-from DIR` reads a folder in the same `<set>/<item>/frozen.json` layout instead (the round-2 snapshots). `--search-only` stops after the search and admission (no retraction check, texts or hops), marks `meta.json` `search_only` and is refused by `experiment run` (`SnapshotSearchOnly`) and by `--rewarm`; only with it may `--n`, `--skip` and `--seed` override the experiment's items. `meta.json` also records `plan_from` (profile and digest), `keyless`, the sources used and the search accounting (`search`: searches and failures per source, results per query, seconds, tolerated failures); the snapshot's `incomplete` marking works as before.
- **Running**: `bench experiment run FILE --out-dir DIR --snapshots DIR --litsearch-dir DATA [--arm NAME ...] [--decision-cache PATH] [--concurrency N]`. `--arm` runs only those arms (always in file order, solo arms last; snapshots are checked only for them; the registry resumes cell by cell). `--decision-cache` is a store file all non-solo cells share their decision answers through. `keyless: true` in the file means no API key is read: the bench builds its `SourceConfig` without either key and never looks them up (`cli._source_config(keyless=True)`; `download litsearch --keyless` does the same for the Semantic Scholar batch endpoint), `run_experiment` refuses a configuration that holds one, and the registry records it. (`load_dotenv()` still runs in `main`, for the model settings; nothing reads the key variables.)
- **`SetSpec.skip`** (litsearch, web): the items are `select_subset(ids, skip + n, seed)[skip:]`, so a larger `n` still extends a smaller one and a skipped set holds the items a smaller subset did not (`load_litsearch(skip=)`; items whose gold papers do not resolve drop out after selection and are counted).
- **`Rule.test: no_harm`** (a guard): not accepted when the oriented mean paired difference is below `-margin` or the whole interval is below 0, accepted otherwise; there is no inconclusive (round 2 measured the paired claim-precision interval at about +-0.08 on 15 items, so a 0.05 non-inferiority bar could not be met whatever the truth). The gating check that makes a rule resting on fewer items than ran inconclusive does not apply to it; the statement names the item count. With no item that has a value for both arms it is inconclusive.
- **Metrics added**: `inputs_failed_search_share` (litsearch, frozen: failed / attempted searches of the item's snapshot, all sources; absent for a snapshot without accounting) and `decision_answers` (every v2 cell: requests plus cache hits).
- **Report** (`bench experiment report FILE --out-dir DIR [--snapshots DIR] [--litsearch-dir DATA]`): for a file that declares profiles it adds the profiles and their hashes, the decision answers per arm, the loss table per arm (with `--litsearch-dir`) and, with `--snapshots` too, each profile's search accounting and candidate pool. For a file that does not, the report is byte for byte what it was (`test_a_report_of_a_file_without_profiles_is_what_the_earlier_code_wrote`, whose fixtures were written by the code before round 3; the real round-2 registry reproduces `round2-report.md` the same way).
- **Loss table** (`pool.classify_gold`, `pool.loss_section`): each gold paper of each run is `hit` (kept, ranked 20 or better), `(c)` kept but ranked below 20, `(b)` screened and dropped, `(b')` in the pool but never screened, `(a)` not in the pool, `(x)` kept then excluded (retracted) or `failed` (no result), read from the run's `works` and its `screening` record.
- **`bench pool --snapshots DIR [--inputs PROFILE] --dir DATA [--n N --skip K] [--against DIR [--against-inputs PROFILE]]`**: the candidate-pool tables of any snapshot root (round-2 layout included), no model and no network: gold papers in the pool, in the top 20 of some query's list, which source found them (and alone), pool size and share per source, queries with fewer than 20 results per source (`n/a` for snapshots that predate the accounting), and with `--against` the gold papers that entered or left the pool and through which source.
- **Patient schedule bounds** (`sources/base.py`): waits 5, 10, 20, 40, 60, 60, 60, 60 s; a `Retry-After` up to `PATIENT_MAX_RETRY_AFTER_S` (120) is honoured, a longer one is never answered early (the request counts as exhausted); `PATIENT_GIVE_UP_AFTER` (3) exhausted requests in a row refuse the source; and `PATIENT_MAX_TOTAL_WAIT_S` (2700) caps the seconds a process waits on one patient source, so a pool that answers one request in five (which never trips the "in a row" rule) cannot hold a freeze for hours: past the cap the source is refused and its remaining searches count as failed, which rule H1 judges. Time estimate for the Semantic Scholar term, at the measured 67% keyless 429 rate: about 30-40 s of waiting per search, so the `r3-combined` freeze is bounded by the 45 minutes of waiting plus the requests themselves.
- **Snapshot identity at run time** (`experiment_run.mismatched_snapshots`, `SnapshotMismatch`): before a frozen arm runs, each needed snapshot of a non-`existing` profile must record that profile's name and hash, the experiment's keylessness and, for a profile that takes its plan from another, the digest of that profile's snapshot of the same item. `bench freeze --plan-from` is allowed only with `--search-only`.
- **Run order** (the spec's variables: `DATA` the LitSearch directory, `SNAP` the snapshots root, `CACHE` the shared HTTP cache, `OUT` the output folder, `X` this file, `B` `uv run python -m andamentum.deep_research.v2.bench`): `$B download litsearch --dir $DATA --n 60 --seed 0 --keyless` (gold for positions 29-60); `$B freeze litsearch --experiment $X --inputs r3-base --snapshots $SNAP --dir $DATA --model ollama:gemma4:31b-cloud --decision-model nimble:9b --cache $CACHE --concurrency 4` alone, then copy the round-2 `web` snapshots to `$SNAP/web-r1/web`; `$B experiment run $X --arm v2-baseline --out-dir $OUT --snapshots $SNAP --litsearch-dir $DATA --decision-cache $OUT/decisions.db --concurrency 4` while `$B freeze ... --inputs r3-arxiv` and `--inputs r3-combined` (no model call) and the seen-item check (`--inputs r3-combined --plan-from <round-2 snapshots> --n 28 --skip 0 --search-only --snapshots <seen root>`) run beside it; then the other arms (`--arm v2-arxiv`, `--arm v2-combined`, `--arm v2-combined-solo`, the last without the shared cache by construction); then `$B experiment report $X --out-dir $OUT --snapshots $SNAP --litsearch-dir $DATA` and `$B pool` over the round-2 and seen snapshots. Local decision-model calls run strictly one at a time; cloud calls at most 4 at once, and the `r3-base` freeze and the experiment never overlap.

## Pitfalls

- **SearxNG 200 with zero results is not "no results"** (round 1: the legacy module scored 0 on 30 LitSearch queries, silently, while Brave, DuckDuckGo and Google CSE were suspended under load). `unresponsive_engines` is a list of `[engine, reason]` pairs; read it on every reply, never cache an empty reply that names one, and never add a second SearxNG client that skips `searxng_search.searxng_query`. A timeout reason is not retried (waiting does not help); a rate-limit or CAPTCHA reason is.
- **The HTTP cache has a hard size cap**, `HTTP_CACHE_MAX_BYTES` (200 MB; `ResearchStore(max_cache_bytes=)`), enforced on every write: expired rows, then least recently used (`http_cache.last_used`, touched on a read; `size` is the body's bytes; schema version 2). An evicted row's blob is deleted unless a cache row, work or passage still names it. `andamentum-research cache-info --cache PATH` and `cache-prune --cache PATH [--max-bytes N]` show and trim a file.
- Reciprocal-rank fusion rewards agreement between lists: a work two sources both returned outranks one with a higher screen score from a single source. That is the method, not a bug; a variant that weights the screen list is a new strategy and a new preset.
- Work ids are random (`w_<uuid>`), and several orderings break ties by work id (`read_targets`, `expansion_seeds`, the result's `works`). Two live runs over fresh stores can therefore read tied works in a different order; frozen repeats over one snapshot store reuse the stored ids and do not.

- An adapter returns what the API gave; it never invents a verdict. `OpenAlex is_retracted` true becomes `retracted`, false stays `unknown` (only Crossref says `no`).
- The licence describes the abstract (`references.merge_works`): a Semantic Scholar record merged with an OpenAlex or Europe PMC record that holds an abstract keeps the redistributable abstract and its licence, so turning S2 on never costs an abstract-only work its evidence. Only an S2 abstract with no free one beside it stays `no_redistribute`, and such an abstract is never read, recorded as a passage or exported.
- A paywalled publisher's open-access PDF is refused by the fetch gate unless its host is in `tdm_allowed_hosts`; the reader falls back to the abstract.

- `Work` raises on a non-empty identifier that is not one (a garbled DOI is a bug in the adapter, not data). Adapters call the `normalise_*` functions on doubtful values first.
- Never merge on the title alone when the two records hold different DOIs (or any disagreeing identifier): that would fold a preprint into its journal version.
- `Candidate.snippet` is the first 500 characters of the abstract, so it follows its work's licence on every dump the same way (`Candidate._licensed_snippet`; it was exported before round 3). `identity.merge_pair` does not carry a restricted record's snippet into a merged work that is redistributable. A frozen run reads restricted text back from the snapshot store.
- `Work` serialises a `no_redistribute` abstract as `""` (a `field_serializer`), so every dump (`ResearchResult.model_dump_json`, the MCP payloads, compose's `evidence/research.json`) follows the licence from one place. The store keeps the text in its own column, not through a dump; a `ResearchResult` read back from JSON therefore carries no restricted abstract.
- Source text reaches a language-model prompt only through `ask.fence` with `ask.UNTRUSTED` in the instructions (passage selection, extraction, yes/no batches, the writer's findings, the criteria prompts). The fence arrows grow longer than any run of arrows inside the text, so a page cannot close its own fence, and the text stays unaltered so a quote still matches. Decision-model states are not fenced: that model returns probabilities, not text. A new prompt that carries fetched text or a claim drawn from it must use both; `tests/test_untrusted.py` pins each site.
- A decision-model answer with no probability raises `AskError` (`Asker.ask_criteria`); the novelty check never reads it as zero.
