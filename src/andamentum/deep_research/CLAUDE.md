# deep_research — notes for Claude

The evidence-first research engine: a model-driven loop over web and scholarly sources, a research store, findings with code-checked quotes, a report that cites findings by id. It is the package's one engine; there is no second pipeline. Layering: `deep_research` imports `core`, `references` and `harvest` (the page extractor, `content_extractor.py`) and nothing else, never `epistemic`, `document_store`, `compose` or `whetstone` (`tests/test_layering.py`).

Entry point: `await research(question, *, mode, model, store=None, budget=Budget(), sources=SourceConfig(), source_client=None, http_cache=None, browser=None, progress=None, clock=time.monotonic) -> ResearchResult` (`engine.py`). `mode` is `web` (the isolated Chrome, `SourceConfig.browser`, or SearxNG, `searxng_url`; one is required), `scholarly` (OpenAlex, Europe PMC, arXiv, optionally Semantic Scholar and a local corpus) or `both`. `model` is the one language model; the engine uses nothing else. From the shell (`ask` is the default command, so the word `ask` is optional; `--mode web|both` needs `--searxng-url` or `--browser`; `--mailto EMAIL` is the polite-pool contact address, with `OPENALEX_EMAIL` from the environment as the fallback): `andamentum-research ask "QUESTION" --mode {web,scholarly,both} --model M [--depth {quick,standard,deep}] [--store PATH] [--cache PATH] [--searxng-url URL | --browser] [--mailto EMAIL] [--local-corpus PATH] [--tdm-host HOST] [--json] [-o DIR] [--quiet]` (`cli.py`; exit 0 clean, 1 degraded, 2 usage, 3 input unreadable, 4 run failed). The command line offers a preset, not knobs: `--depth` picks `Budget.for_depth(depth)` (`Depth` in `types.py`; `standard`, the default, is `Budget()` exactly; `quick` is 1 round, 2 queries, 3 reads, expand 10, 60 calls, 900 s, 20 MB; `deep` is 5 rounds, 4 queries, 8 reads, a 30,000-character window, expand 40, 500 calls, 7200 s, 150 MB; quick and deep are starting points, not measured). `concurrency` is not in a depth (4, a local model held to 1). The scholarly sources are always the default three; `--local-corpus PATH` adds `local_corpus` to them. Every other setting (each `Budget` field, `SourceConfig.scholarly` with Semantic Scholar, `openalex_search`, `results_per_query`) is a keyword argument of `research()` only, which the benchmark and the tests use. Cache upkeep: `andamentum-research cache info --cache PATH` and `cache prune` (`cache_cli.py`). Errors derive from `ResearchError` (`errors.py`: `StoreError`, `SourceError`, `ReportWriterError`); `BudgetExhausted` stays internal, a spent bound is a `stop_reason`. Over MCP: `andamentum-research mcp --store PATH` (`mcp_server.py`). Whetstone's novelty check calls `run_novelty_check` (`novelty.py`). The citation finder is `find_works` (`finder.py`, see below).

## The idea

A research system is a closed loop: decide what is missing, search, choose what to read, read, record evidence, judge whether the question is answered, loop or write. The model makes those decisions with the evidence in front of it; code does what code does better: the tools (search, fetch), de-duplication by work identity, quote checking, id bookkeeping, budgets. There is no decision model, no screening stage and no frozen replay on this path (the CLI's `--depth` names a budget, it adds no stage): every fixed-stage filter between the model and the evidence lost recall, and every one was a knob to tune. Replaying a run is the store's HTTP cache.

## What exists

- `types.py` — every record of a run: `SubQuestion`, `Candidate` (a `references.Work` plus where it came from and its place in each source's list), `Passage`, `RawFinding` and `Finding` (a claim, its quote, `quote_verified`), `PageReading`, `SubQuestionResult`, `VerifyFlag`, `Budget`, `RunStats`, `LogEvent`/`RunLog`, `ResearchResult` (with `cited_work_ids()` and `to_csl()`). A `Passage` is content-addressed (`passage_id = sha256(work_id + text)`) and an exact slice (`end - start == len(text)`); both are checked at construction. A report cites findings as `[F12]`; `cited_work_ids` reads only that bracket form.
- `identity.py` — `merge(candidates)`: one candidate per work. Keys come from `Work.identity_keys()` (DOI, arXiv id, PMID, PMCID, OpenAlex id, Semantic Scholar id, local-corpus id, canonical URL, title+year). A shared hard key merges, transitively; the title key merges only when `works_compatible` (no identifier both sides hold disagrees), so a preprint and its published version stay two works. A title key needs a year and 15+ normalised characters.
- `store.py` — `ResearchStore(path)` / `ResearchStore.in_memory()`. See below.
- `sources/` — the adapters, see below.
- `ask.py` — `Asker`, the one place the run's model is called: step-tagged, counted before the await (so `max_llm_calls` is exact under concurrency), budget-checked (`reserve` keeps the last calls for the writer), logged, one semaphore (`Budget.concurrency`, 1 for a local model). `MODEL_ERRORS` names what a failed model call raises; every caller catches exactly that tuple. `fence` and `UNTRUSTED` carry fetched text into a prompt.
- `engine.py` — `research()` and the per-sub-question task; `plan.py`, `queries.py`, `search.py`, `choose.py`, `reflect.py`, `read.py`, `write.py`, `verify.py`, `fusion.py`, `origin.py`, `lexical.py`, `runlog.py` — the steps, see below. Plain async functions, no graph engine: the engine routes and assigns state, the step modules compute and return values, every loop and fan-out is bounded by a `Budget` value or a named constant, and the model answers questions and never drives the flow.
- `finder.py` — `find_works`, the citation finder: one sentence in, ranked works out (metadata only), see below.
- `novelty.py` — the novelty check whetstone calls, see below. `bench/` — the benchmark harness and loss attribution, see below. `searxng_search.py`, `browser_search.py`, `content_extractor.py` and `cache_cli.py` are the helper modules at the package root: the one SearxNG client, the Chrome search (`browser/` is the isolated Chrome itself), the page extractor (harvest) and the cache commands (`cache info` / `cache prune`).

## The store

One SQLite file (WAL) and a `blobs/` folder beside it; the caller always names the path. No default location, nothing under the home directory. A lab can keep one store for all projects; compose passes `<doc>.harness/research.db` (Word) or `<bundle>/research.db` (bundle), whetstone's `NoveltyResearch(store=PATH)` (Python only) a path of the caller's choosing. `in_memory()` leaves nothing behind.

- **Blobs** are named by sha256. Up to `INLINE_BLOB_LIMIT` (16 KiB) they sit in the `blobs_inline` table, above it in `blobs/<aa>/<sha>` (written to a temporary name, then renamed). Every `*_blob` column holds a digest.
- **HTTP cache**: `cache_key(source, url, params)`, `cache_get` (None once the TTL has run out), `cache_put`. TTL constants: `TTL_SEARCH_S` 7 days, `TTL_METADATA_S` 30, `TTL_FULL_TEXT_S` 180. Hits and misses are counted on the store (`cache_hits`, `cache_misses`) for `RunStats`. A row tagged `no_redistribute` is usable inside the store but `iter_cache()` (the export path) leaves it out, and `Work.to_csl()` omits the abstract of such a work. `reference_cache()` returns the store as the `references.http.Cache` protocol, so Crossref lookups share the cache instead of keeping their own.
- **Shared read-through cache**: `ResearchStore(path, shared_cache=other)` (also `in_memory(shared_cache=)`; `research(http_cache=)`, `--cache PATH` on the CLI and on `bench experiment run`). An own miss (or an expired own row) reads through to the shared store: a live entry there is copied into this store with its original `fetched_at` (the TTL keeps counting from the fetch) and counted as a hit (`shared_hits` too); `cache_put` writes to both. Every path goes through `cache_get` / `cache_put`, so adapters, `keep_text`, Crossref (`ReferenceCache`) and the retraction check are all covered. `any_age` reads (an offline client) never consult the shared store. A row's licence travels with the copy: `no_redistribute` entries are usable in both stores and left out of `iter_cache()` in both. The run's own store therefore holds exactly the entries it used. `import_cache(source_db)` merges another store file's `http_cache` rows and blobs (opened read-only; freshest `fetched_at` per key wins; an expired row, an unreadable blob and a row no fresher than the held one are counted, not imported; counts by `source`). `research(http_cache=)` is refused with an open `store` (open that with `shared_cache=`).
- **Works**: `upsert_work` merges with every stored work sharing any identifier (all eight have a unique index; absent identifiers are NULL). A record that bridges two stored works merges them into the older one; the other id keeps resolving (`work_aliases`, `resolve_work_id`). Passages keep the id they were addressed with, so `passages_for_work` includes those of the aliases, and anything that holds an old id resolves it through the store. A merge only raises `access` and `retracted`; `set_work_state` is the one way to overwrite them after a fresh check.
- **Runs**: `start_run` / `finish_run`, `add_run_item(kind, ref_id, data)` (a row with the same kind and ref id is replaced; kinds are `RunItemKind`: `subquestion`, `finding`, `flag`, `log`).
- Schema changes are migrations by version number in `_MIGRATIONS` (version 4 adds `works.local_id`, the identifier of a record in a local corpus; versions 6 and 7 drop the tables of a decision model the package no longer has: its answer cache, determinism check, embedding cache and audit trail); a database from a newer version is refused with `StoreError`. No shims for old development files.
- One writer per process: every public method takes the store's lock.

## The loop (`engine.py`)

```
Plan                  1 call: 1 sub-question when the question asks one thing, at most 4 when it has parts
per sub-question, in parallel (asyncio.gather; the Asker's semaphore caps model calls in flight):
  round 1 .. Budget.max_rounds (3):
    stop if a bound is spent (wall time, model calls, fetched bytes)
    queries   round 1: one call (queries.py), and the sub-question's own text is searched too;
              later rounds: reflect's next_queries (no call), or one call with the gaps when it gave none
    search    every query on every source of the mode; results merged by work identity; snippets kept
    expand    scholarly/both, round 2 on: one citation hop from the best works read so far
    choose    one call: titles, sites, years and snippets of the UNREAD results -> up to K picks (reads_per_round, 5)
              and up to K reserves
    read      the picks in parallel; an unreadable pick is replaced by the next reserve (each used once)
    reflect   one call: answered?, the best-supported answer, the gaps, next queries; stop when answered
number the findings F1.. (sub-question order, round order, pick order: deterministic)
Write                 1 call over all findings of all sub-questions
Verify                code only
Finish                ranked works, stats, result
```

- **Effort scales with the question.** A simple fact is one sub-question and usually one round: about 10 model calls (plan, queries, choose, five notes, reflect, write).
- **Sub-question state is separate** (candidates, what was read, findings, queries run) and merged in sub-question order when all have finished, so finding ids and the ranking do not depend on which task was faster. A work found by two sub-questions can be read twice, once for each. While a sub-question runs its findings are numbered 1..n locally, never `F#`.
- **Stop reasons.** Per sub-question: `answered`, `rounds` (the cap), or `budget:<name>` (`max_wall_s`, `max_llm_calls`, `max_fetch_bytes`). Run level: `answered` when every sub-question was; else the first `budget:...`; else `rounds`. `max_llm_calls` counts as spent when `write_reserve(n)` = 1 + n calls are left (n sub-questions, known after the plan; 2 until then): the joint write call plus one call per section that stays empty, so the report always has its calls. A spent bound is a result, never an exception, and the writer still runs on whatever exists. A sub-question that read nothing gets the fixed line `No evidence could be read for this question.`, not silence.
- **Failures** follow one rule: a `SourceError` is recorded in `degraded` (a routine refusal or an offline miss is a note) and the other sources go on; a failed model call is recorded in `degraded` and the step falls back (choose to the top candidates by fused rank, reflect to "not answered"). The writer has no fallback: a section it cannot get written raises `ReportWriterError`. Unreadable pages above half of those tried make the run degraded (`read.unreadable_degraded`). Anything else raises: the run is recorded as failed in the store first, and the log so far is the error's `run_log`.
- **`research()` owns what it opens**: a store from a path or `None` (in memory) is closed at the end, a store passed open is not. `http_cache` is a shared read-through cache and cannot be combined with an open `store`.
- **Local models** are never called concurrently (semaphore 1).

### Reading (`read.py`, `lexical.py`, `sources/browser_fetch.py`)

- **Order per page**: Crossref retraction check for a work with a DOI (a retracted work is excluded, not read); text from the first text source that has it; else the redistributable abstract; else a search snippet of at least 80 characters (`via="snippet"`: a snippet is evidence, an unreadable page is not a reason to know nothing); else nothing (`access` `unreadable` when a source failed, else `metadata`).
- **Chrome fallback**: `WebSource.fetch_text` reads the page through the same isolated Chrome (`browser_page_text`: a new tab in a new browser context, navigate, wait for the load event, poll `innerText` until it stops growing, at most ~3 s) only when the plain fetch failed with `http`, `parse` or `transport`, a browser session is set, and the URL is not a PDF. At most 3 tabs at once. The final `href` must pass `core.url_safety.is_safe_url` or the text is discarded; a short page (under 2,000 characters) with bot-check wording is a 403 `SourceError`, not text. The text goes through `client.keep_text`, so the cache and replay work. A replayed Chrome page reports `via="fetched"` (the cache keeps no marker).
- **Window, not snippets**: a page is cut to the most relevant `Budget.window_chars` (20,000) characters: `split_passages` (~1,200 characters, exact slices), BM25 (`lexical.py`) against the sub-question plus the round's queries (never the raw question alone: that favours pages that echo it), best first until the limit, restored to document order, passages that touch merged into one span. A page within the limit is one passage, whole. If loss attribution shows the answer disappearing at `notes_input`, raise `window_chars` (one number).
- **Notes**: one model call per page (pages in parallel), flat schema `{findings: [{passage, claim, quote}]}`, at most 8 kept, duplicates dropped. The quote must be copied character for character, without `\n`, `\t` or ellipsis.
- **Soft quote check** (`locate_quote`, `check_quote`): exact; then folded (case, width, quote marks, dashes, whitespace); then visible text (Markdown links, citation markers, emphasis, table pipes and separator rows). A literal backslash-n or backslash-t in the quote reads as a space. An elided quote is not matched: verbatim means verbatim. Located: the finding's quote is the passage's own words and `quote_verified=True`. Not located: the finding is kept with the model's quote and `quote_verified=False`, visible in the report (`[quote not verified]`), the run log and `RunStats.quotes_unverified`. Nothing is dropped silently. Compose uses only verified findings.

### Writing and verifying (`write.py`, `verify.py`, `fusion.py`)

- **Write** is one call over all sub-questions with findings. Per sub-question: its text, the reflect draft answer (fenced, labelled unverified: "keep it only where findings support it"), then the findings (id, claim, quote, source title, origin label, year, an unverified marker), at most 30 per section, spread over origins. The rules are prompt text: the best-supported answer first; weigh by source quality (primary, official and encyclopedic over aggregators, forums and content farms), by the number of independent origins (`origin.py`), by the time scope the question asks; report a disagreement only when it is real and unresolved, after the answer; an unverified quote is weaker; commit and say how sure in words. Output `{sections: [{subquestion, sentences: [{text, finding_ids}]}]}`; the schema requires `sentences` with at least one item (`min_length=1`, no default) and the validator rejects an empty section or a sentence that is only citations (named in the retry), unknown ids and a sentence without ids; code appends `[F..]`. A section still empty after the retries is written by its own call for that sub-question only; if that fails (or the budget is spent) `write_report` raises `ReportWriterError` (exported from `deep_research`; names the sub-question and the reason) and the run is recorded as failed. There is no plain-claims fallback and no `Report.degraded`. Root cause of the former empty sections (measured with `ollama:gemma4:31b-cloud`, 10 of 10 joint calls empty on a two-section input): the model's first answer was a flat `{id, text, finding_ids}` section, schema validation rejected it, and the repair filled the then-optional `sentences` with `[]`, which is valid. Requiring the list makes the repair write prose (8 of 8 repaired in one retry); the shape example in the instructions makes the first answer valid (10 of 10 first-try). Code builds the title, a heading per sub-question and `## Sources`.
- **Verify** is code only: a cited `[F#]` exists (`unknown_finding`), a verified quote is still in its passage (`quote_missing`, should never fire), an unverified cited finding (`unverified_quote`, and a sentence whose cited findings are all unverified gets the mark), a retracted work or DOI (`retracted`), links and DOIs in the report (`dead_link`, `doi_unresolved`).
- **Ranked works** (`fusion.rank_works`): works behind cited findings in order of first citation; then the other works that were chosen and read; then every remaining candidate; the last two groups by reciprocal rank fusion of the candidates' places in each source's list (`RRF_K` 60). A tie keeps the order of the read or the candidates, never the work id. Retracted works never appear. LitSearch recall@20 and compose read this order.

### The run log (`runlog.py`, `types.RunLog`)

On for every run (API, CLI, MCP, bench). `RunLogger.event(event, message, *, step, **data)`; `step` is explicit, never ambient. `RunLog.to_jsonl()` (a header line with the run id, then one event a line; `from_jsonl` reads it back) and `to_markdown()` (a heading each time the step changes, tables for queries, chosen works, findings, model calls and flags). With a store the log is also the run item `log/run`. Text is not truncated in the data, except `fetched.text` (clipped at `runlog.TEXT_CHARS`, 200,000, with `truncated`); the Markdown view truncates cells. Full text is what makes loss attribution possible. Events by step:

- Setup: `config`, `models`, `sources`. Plan: `subquestion`. Search: `round_start`, `queries` (with origin `writer`, `reflect` or `own text`), `query` (per query and source: count, top titles, error), `search_results` (rank, url, title, host, full snippet), `admitted`. Expand: `expanded`. Choose: `choice` (picks, reserves, not chosen, fallback), `chosen_work`. Read: `fetched` (via, ok, chars, status, error, text), `unreadable`, `excluded`. Notes: `notes_input` (the exact text given to the model, window spans), `finding_noted` (claim, quote, verified), `notes`. Reflect: `reflect` (answered, answer, confidence, gaps, next queries), `subquestion_done`. Write: `report` (the full text). Verify: `verify_flag`. Finish: `final_ranking`, `finished` or `failed`. Any step: `llm_call` (purpose, model, prompt size, seconds, output's first 500 characters, error), `degraded`, `note`, `skipped`, `budget_spent`.
- **Where the files go.** CLI: `log.md` and `log.jsonl` in the `-o DIR` folder, next to `report.md` (or `report.json`); without `-o` no log file is written (the log is in the result, so `--json` carries it); a failed run writes its partial log (with `-o`) before exiting 4. Bench: every cell writes `<out-dir>/logs/<arm>/<item>-r<repeat>.log.md` and `.jsonl`. MCP: the `research` tool's result carries `log`.
- `RunStats.step_seconds` is busy seconds summed over concurrent tasks (it can exceed `wall_s`); `step_llm_calls` counts calls per step. `stats.step_seconds["Read"]` covers the fetch and the notes call.

## Sources (`sources/`)

One protocol, six adapters, one shared HTTP client. `Source.search(query, *, limit, filters)` raises `SourceError` and never returns `[]` for a failure; `TextSource.fetch_text(work)` returns `FetchedText` or `None` ("no text here", not an error); `ExpandingSource.references/citations(work, *, limit)`. They are separate runtime-checkable protocols, so the engine asks `isinstance`. `SourceError` carries `source`, `reason`, `kind` (`http`, `transport`, `rate_limited`, `refused`, `parse`, `config`, `offline`), `status`, `url`, `retry_after_s`; an `offline` error is an offline client's cache miss (a skip, never degraded); a `refused` fetch (SSRF, robots.txt, the paywalled-publisher list) is the gate working, not a broken source. Every adapter is built `Class(store=store)` (the MCP server does this) or `Class(client=client)`; built from a store alone it uses `SourceClient.for_store(store)`, one client per store, so request spacing holds across adapters and tool calls. `build_sources(config, *, store, mode)` returns a `SourceSet(client, search, text, expand, crossref)`; `SourceConfig` holds every secret and address as an explicit field (`mailto`, `openalex_api_key`, `semantic_scholar_api_key`, `searxng_url`, `browser` (a bool: the isolated Chrome), `tdm_allowed_hosts`, `scholarly`, `arxiv_query`, `expand_with`, `openalex_search`, `arxiv_pdf_interval_s`). `arxiv_query` (`all_terms`, the default, or `any_term`) joins the words of an arXiv query by AND or OR; `expand_with` (`None`: every source that has citation links, as before) limits which sources `SourceSet.expand` holds, so a source can be searched and read without being asked for citation hops.

- **`SourceClient`** (`base.py`): `get` / `get_json` read the store cache first (key = source + URL + `params`; `auth_params` and `headers` are sent but never keyed or stored, so a key is not written into the cache and one answer serves every caller), space network requests per source (a slot is reserved under a short lock and waited for outside it: starts stay `interval` apart while requests overlap in flight, at most `DEFAULT_INFLIGHT` at once: Crossref 3, OpenAlex 4, Europe PMC 2, every other source and each fetched host 1), retry 429/500/502/503/504 (`DEFAULT_RETRIES` 2; the wait is `Retry-After` or 1 s, 2 s; a wait over `MAX_RETRY_WAIT_S` raises at once instead of sleeping), cache only a 200 and only after the adapter's `validate` accepted it (Europe PMC, arXiv and SearxNG answer some failures with a 200 body; none is remembered for a week). It reads `x-ratelimit-*` and `Retry-After` into `rate_info[source]`, adds `x-ratelimit-cost-usd` to `spent_usd[source]`, and once a server says `remaining` is 0 with a reset further than the retry cap it refuses further calls locally (`rate_limited`) rather than hammering it. `fetch_document` is for URLs from the open web or a record: `check_fetch_allowed` (robots.txt, paywall list, `tdm_allowed_hosts`), `fetch_with_safe_redirects` (SSRF on every hop, size cap), `deep_research.content_extractor.extract_content` (harvest), at least `MIN_FULL_TEXT_CHARS` of text, cached as text for `TTL_FULL_TEXT_S`. `get` never follows redirects (API hosts are fixed). `fetched_bytes` and `requests` feed `RunStats`; the `extractor`, `clock` and `sleep` are injectable, so the tests run no network and wait for nothing. **One limiter per source for the process**: a client built on the real clock inside a running loop takes `sources.process_pacing()` (one `SharedPacing` per event loop: request locks, last-start times, in-flight semaphores and the "budget is spent until" marks), so concurrent items and live arms space requests to one source or fetched host as one client would (`DEFAULT_INTERVAL_S`: arXiv 3 s, Semantic Scholar 1 s, Europe PMC 0.2 s, OpenAlex and Crossref 0.1 s; arXiv PDFs 15 s) and a source that said its budget is spent is refused locally by all of them. A client with an injected `clock` or `sleep` (a test double) keeps a private pacing, as does one built outside a loop; pass `pacing=` to choose. `SourceClient(store, offline=True)` (no `client` may be passed; the engine does not use it, replaying a run is the shared HTTP cache's job) never touches the network: `get` and `fetch_document` answer from the cache at any age (`store.cache_get(any_age=True)`) or raise `kind='offline'`, its `http` has a transport that refuses every request with a `ConnectError` (so Crossref through `references` and the link checks reach nothing either), and every miss is counted in `offline_misses` (by source, or by host for `http`). `client.reference_cache()` is the store's `references` cache with the same any-age rule.
- **PDF extraction** (`extraction.py`, `SourceConfig.pdf_extraction` / `SourceClient(pdf_extraction=...)`): `docling` (the library default, unchanged: harvest's docling pipeline, layout-aware, seconds to minutes a paper and gigabytes of memory) or `fast` (the PDF's text layer through pypdfium2: milliseconds, no layout, no OCR; a scan has no text layer and raises `ExtractionError`, so the reader falls back to the abstract; line-end hyphens are joined, paragraphs end at a sentence on a short line). The bench CLI defaults to `fast` (`--pdf-extraction`). Only PDFs differ; HTML goes through harvest either way. `SourceClient(patient=("semantic_scholar",))` gives the named sources the patient schedule (a shared, rate-limited pool): 8 retries waiting `PATIENT_RETRY_WAITS_S` (5, 10, 20, 40, 60, 60, 60, 60 s), a longer `Retry-After` honoured up to `PATIENT_MAX_RETRY_AFTER_S` (120 s), and after `PATIENT_GIVE_UP_AFTER` (3) requests in a row that ran out of retries the source is refused (`rate_limited`, nothing sent) for the rest of the process (the count and the refusal live in `SharedPacing`, so every client of the process shares them; a success resets the count; a cached answer is still served). Live runs and every other source keep `DEFAULT_RETRIES`. `SourceClient.extractions` maps each fetched URL to the extractor used (`pypdfium2`, `docling`, `harvest-html`, `text`, `custom`).
- **OpenAlex** (`openalex.py`): keyword search is `search.title_abstract_keywords` (stemmed, boolean allowed) with cursor paging (`cursor=*`, `meta.next_cursor`, `per_page` up to 100); `search.semantic` is a separate call (`search_semantic`, or `mode='semantic'|'both'`), one page of at most `SEMANTIC_MAX` (50). References: the work's `referenced_works` (free lookup by `/works/doi:...`, `pmid:`, `pmcid:`, then batches `filter=openalex:W1|W2` of 50); citations: `filter=cites:W...&sort=cited_by_count:desc`. Abstracts arrive as an inverted index and are rebuilt. Text is the work's `open_access.oa_url` through `fetch_document`.
- **Europe PMC** (`europepmc.py`, `jats.py`): `search` with `resultType=core`, cursor paging; filters become `PUB_YEAR:[a TO b]` and `OPEN_ACCESS:y` terms. References/citations from `/{MED|PMC}/{id}/references|citations` (entries have title, authors, year, ids, no abstract); a work with only a DOI is located by a `DOI:"..."` search first. Full text is `/{PMCID}/fullTextXML` read by `jats_to_text` (title, abstract, sections and paragraphs as markdown; formulas, tables, figures and the reference list left out; parsed with `_util.parse_xml`, which resolves no entity and loads no DTD). A 404 is "not in the open-access subset" (`None`).
- **arXiv** (`arxiv.py`): Atom API, `to_search_query(query, *, form)` turns a plain query into up to 8 significant words (3+ letters, stop words out, each once) over `all:` joined by AND (`all_terms`, the default: a long query often finds one work or none) or by OR (`any_term`: ranked by the relevance sort, never empty; same words, same `sortBy=relevance`, same 20 results) (field syntax is passed through; the cache key carries `search_query`, so the two forms never share a row), 3 s between API calls. The PDF comes from `arxiv.org/pdf/<id>` at a 15 s spacing (`ARXIV_PDF_INTERVAL_S`, arxiv.org's robots.txt crawl delay; `export.arxiv.org`, the API host, disallows robots entirely, so PDFs cannot come from it). A year filter is applied after the fetch. Error entries in a 200 feed raise.
- **Semantic Scholar** (`semantic_scholar.py`): optional; `x-api-key` header from `api_key`; no key works but shares a pool and often gets 429 (raised as `rate_limited`). Every work and every cache row is tagged `no_redistribute`. A reference list the publisher withheld comes back `data: null`: an empty list, not an error.
- **Crossref** (`crossref.py`): no client of its own; `references.ReferenceHttp` (sharing the store cache through `store.reference_cache()`) and `lookup_retraction`. `search`, `get_work(doi)`, `retraction_status(doi)` (`retracted` > `concern` > `correction` > `no`; `unknown` for a DOI Crossref lacks; a failed call raises, never reads as `no`). Not in the default scholarly list: it verifies, it does not discover.
- **Web** (`web.py`): with a `browser` session (`SourceConfig.browser`) the search goes through the isolated Chrome (`browser_search.py`, see below; one page of results) and the same Chrome reads pages the plain fetch cannot (`browser_fetch.py`, see Reading); otherwise SearxNG JSON search (explicit `searxng_url`, no default), up to 3 pages, deduplicated by canonical URL. No address at all is a `config` `SourceError` at construction. Every SearxNG query goes through `searxng_search.py` (see Pitfalls and Web search below). Search goes through the shared client because it must be cached and must raise; the fetch reuses the same gate, SSRF layer and extractor.
- PubMed and Unpaywall are not adapters: Europe PMC indexes PubMed, OpenAlex carries the open-access locations.

### Verified against the live services (2026-10-05)

- OpenAlex has changed since the older docs: pagination is `page`/`per_page` or `cursor`; the cost is in the response (`meta.cost_usd`) and in headers `x-ratelimit-cost-usd`, `-credits-used`, `-limit`, `-remaining`, `-reset` (seconds), `-remaining-usd`, `Retry-After`. A keyless caller has 1000 credits a day (a search or semantic search costs 10, a filtered list such as `cites:` or `openalex:` 1, a single-work lookup 0); a free key raises it tenfold. `search=` now means full-text search; the adapter uses `search.title_abstract_keywords`. `search.semantic` exists, cannot be combined with another search, takes about nine seconds and returned 504 `query_timeout` on three of five calls (with no charge): a failure is raised and recorded, and the default mode is keyword. `mailto` is still accepted.
- Europe PMC: `https://www.ebi.ac.uk/europepmc/webservices/rest/search` (`query`, `format=json`, `resultType=core`, `pageSize`, `cursorMark`/`nextCursorMark`); core records nest `authorList.author[]`, `journalInfo.journal.title`, `fullTextUrlList.fullTextUrl[]`, `pubTypeList.pubType[]`; `/{PMCID}/fullTextXML` gives JATS 1.4 with a DOCTYPE; `/{source}/{id}/references` and `/citations` give `referenceList.reference[]` / `citationList.citation[]`. No rate limit is documented.
- arXiv: `https://export.arxiv.org/api/query`, Atom 1.0 (`entry/id` with a version, `title`, `summary`, `author/name`, `published`, `arxiv:doi`, `arxiv:journal_ref`); max 2000 results a request; ToU asks for one request in three seconds; the pages and PDFs of `arxiv.org` carry `Crawl-delay: 15` and allow `/pdf`.
- Semantic Scholar: the Graph API shape (`paperId`, `externalIds`, `openAccessPdf`, `data[].citedPaper|citingPaper`) is from the docs and a recorded reference response; the keyless search answered 429 at once, so the search fixture is synthetic in the documented shape.
- A live smoke run of every adapter (OpenAlex search, references and citations; Europe PMC search and full text; arXiv search; Crossref lookup and retraction) returned sensible works; it is not part of the test suite.

Tests: `tests/test_sources_*.py` with `tests/source_stub.py` (a mock transport, fake clock and sleep) and recorded or synthetic fixtures in `tests/fixtures/` (OpenAlex, Europe PMC and arXiv responses trimmed to two records each; the JATS, Semantic Scholar, Crossref and SearxNG files are invented).

### Web search: SearxNG and the isolated Chrome (`searxng_search.py`, `browser_search.py`)

- **SearxNG blocked is a failure, not an empty list.** `searxng_query` is the one client. A reply with no results and an unresponsive engine raises `SearchEnginesBlocked` (the `(engine, reason)` pairs; never cached); when every reason is a rate limit or CAPTCHA the query is retried after 5 s and 15 s (`SEARXNG_RETRIES` 3 attempts, `SEARXNG_RETRY_DELAYS_S`), a timeout is not retried, then it raises, and `WebSource` turns it into `SourceError(kind='rate_limited')` (or `http` when not retryable). A partial answer (some results, an engine down) returns the results with a warning that the search step records in `ResearchResult.notes` (`WebSource.take_warnings`), not as degraded. Queries are spaced `SEARXNG_MIN_INTERVAL_S` (1.5 s) apart by the client's `DEFAULT_INTERVAL_S["web"]` (the process-wide `SharedPacing`, no second limiter). Search answers are cached in the store for a week; with no store and no `cache=` nothing is written. `tests/test_searxng_search.py` pins each rule over a mock transport.
- **Web search through a browser** (`browser_query`): `SourceConfig.browser` (`andamentum-research --browser`, `bench experiment run --browser`, compose `--browser`, epistemic `--browser`) searches and reads through an isolated Chrome instead of SearxNG. Raw CDP over `websockets` (already installed): one `isolated_page` per search page or page read (`browser/cdp.py`), `Page.navigate`, one `Runtime.evaluate` that reads the result list; no language model. DuckDuckGo's HTML page first, Bing when DuckDuckGo shows a bot check (the page's `warning` names it); a page with neither a result list nor the engine's "no results" note is a bot check, and a bot check on every engine raises `SearchEnginesBlocked` (retryable), never `[]`. It returns the same `SearxPage` as `searxng_query`; one page (about ten results) per query; spacing, cache key source and TTL are SearxNG's. The reader takes `innerText || textContent` because a headless Chrome leaves `innerText` empty for rows it has not laid out (Bing). browser-use itself was not added: it pins exact versions of httpx, pydantic, openai, mcp and others (an extra must not move core packages) and ships telemetry.
- **The isolated Chrome** (`browser/`, `browser_session()`): the package starts Chromium in a podman container and removes it. `browser/container/` holds the Containerfile (Debian slim pinned by digest, distribution `chromium`, nothing third-party; the base image is pinned but the apt packages are whatever Debian holds at build time, so the Chromium version moves between builds), `entrypoint.sh` and `browser.sh`; the wheel ships them. The image `andamentum-chrome:<hash of the three files>` is built by `ensure_image` when podman does not hold it (a progress line, about two minutes, 804 MB, once); podman missing is a `BrowserUnavailable` that names podman. `browser_session()` runs `podman run --rm --read-only` with tmpfs for `/profile`, `/tmp` and the home (a fresh profile per container), CDP published on `127.0.0.1` at a random host port, the label `andamentum.browser=deep_research` (tests find containers by it), and removes the container in `finally` with a blocking `podman rm -f`, so cancellation and `KeyboardInterrupt` cannot leave one. One container per `research()` run (the cold start is 0.55 to 0.76 s with the image built; a run takes minutes); a caller that runs many researches opens `browser_session()` once and passes it as `research(browser=...)`, and the MCP server opens one for its lifetime. `SourceConfig.browser` is only the request; the session is the running container, passed to `build_sources(browser=...)` and `WebSource(browser=...)`; no address is an option anywhere.
  - Isolation: the entrypoint starts as root with only NET_ADMIN, SETUID and SETGID, installs an iptables OUTPUT firewall (allow loopback, replies, DNS to the resolvers and the public internet; reject 0/8, 10/8, 100.64/10, 127/8, 169.254/16, 172.16/12, 192.168/16, 198.18/15, 224/3; IPv6 dropped but loopback), then drops to uid 10001 with no capabilities and no-new-privs. Default podman networking does not isolate: without the firewall a page read the Mac's loopback server through `host.containers.internal` and a LAN-bound server on the Mac's LAN address. With it every private target is refused, the LAN included (the live test reports it). Chromium runs `--no-sandbox` (its sandbox needs user namespaces, and every capability is dropped), so the container and the firewall are the isolation. Headless Chromium ignores `--remote-debugging-address` and binds 127.0.0.1:9223 only, so `socat` forwards port 9222. The user agent is the ordinary desktop one of the installed version: `HeadlessChrome` makes DuckDuckGo bot-check every search.
  - Per page: `Target.createBrowserContext`, `Browser.setDownloadBehavior` deny, a tab in that context, `closeTarget` and `disposeBrowserContext` after. No cookie or storage outlives a read; a download leaves no file. The live test (`tests/test_browser_container_live.py`, marker `browser_container`, deselected) proves search and read, no container left, the Mac's loopback and LAN unreachable (navigation and fetch), cookie isolation and the download denial (with an allow-control).
- **The library starts no search service.** It reads no environment variable for an address, writes nothing under the home directory, and runs no SearxNG; that is the caller's. It starts one thing: the isolated Chrome container, when `SourceConfig.browser` is set, and stops it. A failed search raises; `[]` only ever means the search ran and found nothing.

### Local corpus (`sources/local_corpus.py`)

- **`Work.local_id`** (`references/works.py`, `normalise_local_id`): `local:<token>`, the identifier of a record in a local corpus, which has no public id. A hard identity key (kind `local`), a column and unique index of `works`, and a scholarly identifier for `search.is_scholarly` (a corpus holds the citation links, so a record can seed expansion).
- **`LocalCorpusSource`** (name `local_corpus`; search, text and expansion): a corpus folder holds `corpus.jsonl` (`CorpusRecord`: `corpus_id`, `title`, `abstract`, `citations`; a title or abstract may be empty and is never invented); `build_index` derives `corpus.sqlite` once (FTS5 over title + abstract, `porter unicode61`; the citation edges; the byte size of the `corpus.jsonl`, so a changed corpus refuses a stale index with a `config` error). Search is BM25 (the query's words, case-folded and distinct, joined by OR; ties by corpus order). Records are `access="abstract"` with no licence tag. `fetch_text` returns title + abstract; `references` and `citations` read the edges. No client, no cache, no pacing. Read before every network source (`build_sources`).
- **Configuration**: `SourceConfig.local_corpus: Path | None` (explicit; naming the source without it is a `config` error), `local_corpus` in `scholarly` and `expand_with`; on the command line `--local-corpus PATH` adds it to the default scholarly sources. The path is an address on one machine, so `research()` leaves it out of the recorded run configuration.
- **Data** lives in `data/benchmarks/<dataset>/` of the main checkout, ignored by git except `data/README.md` (what each dataset is, its source, licence status and citation). The LitSearch data is local evaluation only; nothing computed from it with records in it is committed.

## MCP server (`mcp_server.py`)

`andamentum-research mcp [--store PATH] [--model M] [--searxng-url URL | --browser]` (stdio; a subcommand of `cli.build_parser()`, like `ask` and `cache info` / `cache prune`; `mcp_server.run(args)` serves it). Without `--store` the store lives in memory. Secrets as for the CLI. Tools, every one writing only to the store:

- `search_works` (sources from `openalex`, `europepmc`, `arxiv`, `semantic_scholar`; each source's failure reported, all failing is an error), `search_web` (needs `--searxng-url` or `--browser`), `expand_citations` (`openalex`, `europepmc` or `semantic_scholar`): adapters from `build_sources` over the server's one `SourceClient`, so spacing and the cache hold across calls; duplicates merged, works stored.
- `read_work`: the stored work and its passages; `fetch` runs `read.load_page` (retraction check, text, the most relevant window as passages; no model); `subquestion` with `run_id` runs `read.read_page` (one notes call, quotes checked in code) and records the findings in the run, numbered after the run's last finding.
- `record_finding`: the quote must be in a stored passage of the work (`read.locate_quote`); the stored quote is the passage's own words. The abstract becomes a passage only when the work's licence allows its use (`Work.redistributable`).
- `get_run`, resources `research://run/<run_id>`, and `research` (the whole engine against the server's own store and client; needs `--model`).

Model-calling tools hold one lock. `tests/test_mcp_server.py` drives the real modules through the SDK's in-memory client over `engine_world`.

## Citation finder (`finder.py`)

`await find_works(sentence, *, model, paragraph=None, follow_citations=True, sources=FINDER_SOURCES, store=None, http_cache=None, source_client=None, clock=time.monotonic) -> FinderResult`: the works one sentence of a draft could cite, best first, from titles, abstracts and identifiers only (no text is read, no quote, no store of findings). Exported from `deep_research` with `FinderResult`, `FinderModelError` and `FINDER_SOURCES` (Semantic Scholar, OpenAlex and Europe PMC searched; Semantic Scholar's citation links followed, one call per list).

```
queries   1 call: 2 or 3 keyword queries from the sentence (the paragraph is context); repeats dropped (queries.fresh_queries)
search    search.search: every query on every source of sources.scholarly, merged by identity, admitted to the store
seeds     follow_citations only, 1 call: the 1 to 3 best of the top SEEDS_SHOWN (30) results by code order
follow    search.expand: references and citers of each seed, one call per list (per_call=LINKS_PER_LIST, 100), never deeper
rank      code order (fusion.rrf_scores of BM25 of title+abstract against the sentence and the candidates' fused source places);
          1 call: the model orders up to RANK_PICKS (20) of the top RANK_SHOWN (50); the rest follow in code order
```

- Every candidate is returned (`works`); `searched`, `seeds`, `followed`, `shown` and `chosen` are work ids of `works`, so a lost gold work can be traced to its step. Two calls without citation following, three with.
- Failures: a source error is recorded in `degraded` in `search.search`'s words (`... search failed for ...`) or as `citation following failed: ...`; the bench reads both as an outage. A model call with no usable answer after its retries (no query left after repeats are dropped, no seed, a number that does not exist), a failed call or a spent call budget raises `FinderModelError` (exported; `step` names the call, `run_log` is the log so far): the finder has no fallback, so every result comes from the steps it names, and the bench records such a cell as failed (its outcomes zero, as any crashed cell), never as a result. An empty ranking is an answer: the code order follows. This differs from the engine's rule above on purpose: a finder result is a measurement of its own steps.
- Candidate text reaches the seed and rank prompts only through `fence` with `UNTRUSTED`. A Semantic Scholar abstract is shown to the model (as `choose` shows snippets) and never exported (`Work`'s serialiser).
- `find_with` is the same over given adapters (the tests pass stand-ins). Tests: `tests/test_finder.py` (stand-in sources, a scripted model, one run over Semantic Scholar's wire format on a mock transport).

## Novelty check (`novelty.py`)

`run_novelty_check(claim, *, model, store=None, sources=SourceConfig(), budget=NOVELTY_BUDGET, source_client=None, progress=None) -> NoveltyReport` is the novelty check whetstone's `--check-novelty` calls (`NoveltyReport`, `SimilarWork` and `Relevance` are defined in `novelty.py`). One model does everything: a scholarly-mode `research()` run searches for work that may already report the claim, then for every finding of a kept work (a retracted or excluded work is never evidence) the same model gives two probabilities in one call, `anticipates` and `related` (step `Verify`, counted against the budget, findings judged one after another). The verdict (`_verdict`, pure) is a function of the answers and the run's health:

- a finding with `anticipates >= ANTICIPATES_AT` (0.5): `is_novel=False`, confidence the highest p; `similar_work` has one entry per work with the finding's quote as the summary (`direct` from `DIRECT_AT` 0.8); a degraded or budget-stopped search does not weaken this (positive evidence);
- no anticipating finding and the search healthy (no `degraded`, no `budget:` stop, the call budget not run out before every finding was judged, at least `MIN_WORKS_ASSESSED` (3) works read): `is_novel=True`, confidence `1 - max p`; the assessment says how many judged findings had an unverified quote;
- otherwise `is_novel=None` with the reasons named in the assessment, which is also what a language-model failure (`MODEL_ERRORS`) gives. Anything else raises.

No text is written by a model: the assessment is built from counts and quotes. `NoveltyResearch(sources, store, budget)` is the setup a caller (whetstone) hands around. The two thresholds and the minimum are not calibrated. Tests: `tests/test_novelty.py` over `engine_world` plus the verdict rule on hand-built results.

## Benchmark (`bench/`)

Run with `uv run python -m andamentum.deep_research.bench --help`: `download litsearch-local --dir DIR` (needs the `bench-data` extra), and `experiment run FILE -o DIR` and `experiment report|losses FILE --runs DIR` (`--runs` is the folder `run` wrote into; `-o FILE` sends the text to a file). Three systems (an arm's `system` field): `research` (the engine's `research()`, `ResearchArm` in `arms.py`), `finder` (`find_works` on the query as the sentence, `FinderArm`; the arm's `follow_citations` is required and is the finder's switch; the finder's sources with the bench's keys) and `s2_search` (one Semantic Scholar search with the query text, its top 20 in the service's order, no model, `SemanticScholarArm`; `model` is refused). `finder` and `s2_search` run on `litsearch-web` only; a finder arm's `ArmOutput.finder` keeps the step lists. Two sets: `simpleqa` (answers graded correct / incorrect / not attempted by a grader model neither arm uses; the csv folder is `--simpleqa-dir`) and `litsearch-web` (LitSearch queries searched live; recall@k against gold, matched by `metrics.work_matches`). Every directory is named on the command line; cells run item by item (each arm on the same item in turn) and are recorded append-only in the registry (`registry.py`), so a stopped run resumes with the same command; a search outage stops the run without recording the cell. Experiment files declare sets (`n`, `skip`, `seed` through `subsets.select_subset`: `sha256(seed:id)` order, so a larger `n` extends a smaller one and `skip` makes disjoint sets), arms, baselines, rules (`noninferior`, `superior`, `exceeds_by` (the mean paired difference itself at least the margin; the interval reported, not tested), `no_harm`, `reduced_by`, `at_least`, `at_most`, grouped) and decisions; the verdicts are paired (`stats.py`, `verdicts.py`).

- **Subgroups**: a cell records its item's subgroup (`RunRecord.group`; LitSearch: `query_set`), and the report adds the set's means per subgroup and arm.
- **`experiments/cite-finder-dev.yaml` and `cite-finder-test.yaml`**: the finder against the engine (B1) and plain Semantic Scholar (B2) on LitSearch. Dev: 30 queries (seed 0, positions 201-230), all four arms (B1 and B2 pick nothing), picks the arm (higher mean recall@20, a tie picks F0). Test: 60 queries (positions 231-290), all four arms, run once; the gate is `exceeds_by` 0.10 on recall@20 against B1 and B2 for the picked arm. Both sets are disjoint from each other and from every LitSearch item used before (positions 1-168); `tests/test_cite_finder_sets.py` checks it by code. Run the test file at concurrency 1 (a B1 cell has up to 4 model calls in flight).
- **`experiments/dev-check.yaml`**: the regression check of the loop (20 SimpleQA questions, one arm, no rules); the run commands are in the file's header. Read its report and the loss attribution after a change to the loop and compare with the previous run.
- **Loss attribution** (`attribution.py`, `bench experiment losses FILE --runs DIR [--simpleqa-dir DIR] [--litsearch-local-dir DIR] [--arm NAME] [--only-failed] [--json] [-o FILE]`; code only, no model, no network). For each item that was not graded correct it reads the cell's run log and finds the first stage where the gold answer (normalised, `matching.contains_phrase`) disappears: search snippets, fetched texts, the text given to the notes, findings, the reflect answer, the report. Diagnosis in order: `search_miss`, `not_chosen`, `unreadable`, `window`, `notes`, `reflect`, `write`, `report_wrong`, `no_log`. The output is a table of diagnoses and counts, then one row per failed item with the stage trace. For LitSearch it names, for each gold work, the first of search results, choice, read, cited, ranked top 20 it is missing from. A failed run becomes a diagnosis in seconds; fix the stage it names with a general change (a better tool, a better general prompt), never one tuned to an item.
- **Concurrency** (`concurrency.py`, `--concurrency N`, 1 to 4): more than 1 only when every language model is an Ollama `-cloud` model (`is_cloud_model`, cap `MAX_CLOUD_CONCURRENCY` 4); a local model is refused with a `ValueError` naming it, never lowered silently. The registry's `start` line and the report state the concurrency used; wall times are measured under that load.
- **Data and licences** (checked 2026-10-05). *LitSearch*: the code repository is MIT; the Hugging Face dataset card declares no licence of its own; the corpus derives from S2ORC (ODC-By 1.0). The data stays in the data directory, never committed or redistributed. *SimpleQA*: the csv is supplied by the user.
- **Metrics** (`metrics.py`, pure): correctness, recall@k, wall seconds, cost. A cell that errors counts against its arm (a wrong answer, recall 0); the exit status is 2 when any item failed.
- **Secrets** come from the environment in the CLI only, after `load_dotenv()`: `SEMANTIC_SCHOLAR_API_KEY`, `OPENALEX_API_KEY`, `OPENALEX_EMAIL`. The two tests that touch the network carry `research_eval` (deselected; `uv run pytest -m research_eval`).
- **Patient sources** (`--patient SOURCE`, repeatable; `Services.patient`): every arm opens its own HTTP client with `SourceClient(patient=...)`, so a shared, rate-limited pool (keyless Semantic Scholar) is asked on the patient schedule by every arm alike; the registry's `start` line records the list. A patient request that ran out of retries, or a source given up for the process, is a failed search: the cell is not recorded and the run stops; the same command in a new process resumes it (the give-up and the 45-minute wait cap are per process). The run ends with a `traffic` line per source on stderr (answers 429, patient waits, seconds waited, given up) from the process's `SharedPacing` (`rate_limited`, `patient_waits`, `patient_waited`).
- The OpenAlex keyless daily budget (HTTP 429 "Insufficient budget") resets at 08:00 local (midnight UTC); on a 429 the run stops without recording the cell and the same command resumes.

## Pitfalls

- **SearxNG 200 with zero results is not "no results"** (round 1: an earlier module scored 0 on 30 LitSearch queries, silently, while Brave, DuckDuckGo and Google CSE were suspended under load). `unresponsive_engines` is a list of `[engine, reason]` pairs; read it on every reply, never cache an empty reply that names one, and never add a second SearxNG client that skips `searxng_search.searxng_query`. A timeout reason is not retried (waiting does not help); a rate-limit or CAPTCHA reason is.
- **The HTTP cache has a hard size cap**, `HTTP_CACHE_MAX_BYTES` (200 MB; `ResearchStore(max_cache_bytes=)`), enforced on every write: expired rows, then least recently used (`http_cache.last_used`, touched on a read; `size` is the body's bytes; schema version 2). An evicted row's blob is deleted unless a cache row, work or passage still names it. `andamentum-research cache info --cache PATH` and `cache prune --cache PATH [--max-bytes N]` show and trim a file.
- Reciprocal-rank fusion rewards agreement between lists: a work two sources both returned outranks one that ranked higher in a single source. That is the method, not a bug.
- Work ids are random (`w_<uuid>`), so no ordering may break a tie by work id: `choose`, `expansion_seeds` and `rank_works` keep the order of the candidates (or of the pages read) instead. A new ordering that sorted by id would make two runs over fresh stores differ.

- An adapter returns what the API gave; it never invents a verdict. `OpenAlex is_retracted` true becomes `retracted`, false stays `unknown` (only Crossref says `no`).
- The licence describes the abstract (`references.merge_works`): a Semantic Scholar record merged with an OpenAlex or Europe PMC record that holds an abstract keeps the redistributable abstract and its licence, so turning S2 on never costs an abstract-only work its evidence. Only an S2 abstract with no free one beside it stays `no_redistribute`, and such an abstract is never read, recorded as a passage or exported.
- A paywalled publisher's open-access PDF is refused by the fetch gate unless its host is in `tdm_allowed_hosts`; the reader falls back to the abstract.

- `Work` raises on a non-empty identifier that is not one (a garbled DOI is a bug in the adapter, not data). Adapters call the `normalise_*` functions on doubtful values first.
- Never merge on the title alone when the two records hold different DOIs (or any disagreeing identifier): that would fold a preprint into its journal version.
- `Candidate.snippet` is the first 500 characters of the abstract, so it follows its work's licence on every dump the same way (`Candidate._licensed_snippet`). `identity.merge_pair` does not carry a restricted record's snippet into a merged work that is redistributable.
- `Work` serialises a `no_redistribute` abstract as `""` (a `field_serializer`), so every dump (`ResearchResult.model_dump_json`, the MCP payloads, compose's `evidence/research.json`) follows the licence from one place. The store keeps the text in its own column, not through a dump; a `ResearchResult` read back from JSON therefore carries no restricted abstract.
- Source text reaches a language-model prompt only through `ask.fence` with `ask.UNTRUSTED` in the instructions (choose, queries, the notes, reflect and the writer's findings). The fence arrows grow longer than any run of arrows inside the text, so a page cannot close its own fence, and the text stays unaltered so a quote still matches. A new prompt that carries fetched text or a claim drawn from it must use both; `tests/test_untrusted.py` pins each site.
