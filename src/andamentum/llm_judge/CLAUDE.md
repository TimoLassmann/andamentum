## Overview

- `andamentum.llm_judge` — LLM-as-judge primitive. Two async entry points: `await judge_score(output, *, criteria=None, context=None, model=...)` (score ONE output per-criterion) and `await judge_compare(output_a, output_b, *, ...)` (which of TWO is better). No graph — one call, or a sequential fan-out with a deterministic roll-up. **Mode lives in the `model` parameter's type**: a `str` → FAST path (one judge, temperature 0, reproducible); a `Sequence[str]` → PANEL path (one call per model, strictly sequential, sampling temperature 0.7 so a same-model-repeated panel actually varies). Every verdict is a *verbalized distribution* (reasoning first, then belief points over three outcomes), from which `confidence` (max mass) and `doubt` (normalized Shannon entropy) are DERIVED — never asked of the model. `judge_compare` always runs BOTH presentation orders and averages, because a single-order call has position bias. Panel pooling is **an agreement gate, not an accuracy boost**: the verdict is the majority vote, `confidence`/`doubt` aggregate conservatively (min / max), and a split panel or an order flip sets `needs_review=True` — a routing hint that never blocks the caller. `doubt` is a **suspicion-raiser only**: high doubt warrants escalation; low doubt never proves the verdict correct (and the signal is noise on nano-class models). Criteria default to six domain-agnostic axes; callers pass their own for a domain.

## Layering

- `llm_judge` depends only on `core` (for `resolve_model`), `pydantic` + `pydantic-ai`. It owns its own pydantic-ai `Agent` construction rather than routing through `core.AgentRunner`, because it needs `model_settings` (temperature) as a first-class parameter — the fast/panel temperature split is load-bearing, not cosmetic. MUST NOT depend on `epistemic`, `deep_research`, `document_store`, `whetstone`, `compose`, `figures`, `typeset`, `chunker`, `harvest`, `vision_critique`, or `proofread`, and MUST NOT import `pydantic-graph` (there is nothing to route between — see the module docstring). Other modules MAY depend on `llm_judge` to score or rank outputs. A dialect-conformance test (`tests/test_dialect_conformance.py`) enforces the forbidden-import list and runs `agentic_dialect.check_code` in strict mode.
