# andamentum.compose.harness.respond — notes for Claude

Claude Code loads this file when it reads files in this directory. Read `../CLAUDE.md` first (kernel, writer and check rules this code relies on).

`andamentum-compose respond FILE.docx [--reviews FILE] [--model M] [--decision-model M] [--out] [--report] [--project] [--results] [--mailto] [--offline]`: comment threads and reviewers' reports as a work queue. Never edits the input; writes `<stem>.responded.docx`, `<stem>.responded.md` / `.json` and, with `--reviews`, `response-letter.docx` / `.md` beside the copy. Exit 0 everything handled, 4 written but open issues remain (items for the authors, review points that could not be verified, refused operations, check errors in collaborators' changes), 2 usage, 3 crash. A model is needed only when there are items (`--reviews` always needs one).

Files: `items.py` (threads and review points), `triage.py` (prompts and per-category workers), `edits.py` (rewrite to span operations), `quotes.py` (quote verification), `collab.py` (collaborators' changes), `letter.py`, `run.py` (orchestration, report, verb).

## Rules the code keeps

- **Items.** A thread is an item when its root is unresolved (root or any reply `w15:done` counts as resolved), was not started by the harness (author starting with `andamentum`), and the harness did not reply last, so a second run does not answer twice. Review points come from one model call per 30000-character chunk; each point's `quote` must occur in the reviews text (whitespace and typographic quotes ignored). A point that does not verify is reported (`unverified_points`) and never answered.
- **Reviews files:** `.txt` / `.md` are read as written; `.docx` / `.pdf` go through `harvest.extract` (not covered by a real-file test; the test stubs `harvest.extract`).
- **Every model claim about the document is a quote, verified in code.** An `edit` whose paragraph cannot be found (no anchor, no verified `target_quote`), an `answer` with no verified evidence quote (or `answerable` false) and a `done` with no verified passage become `author` with the reason in `Outcome.demoted`. The model never gives offsets.
- **Edits are span operations made by code.** The model returns the whole new paragraph; `edits.span_ops` diffs it against the current text by words and emits `Replace` / `Insert` / `Delete` with `expect`. Refused before anything is written: more than one paragraph, empty, unchanged, empty source paragraph, or any operation that touches a citation field result (the writer refuses those anyway; refusing early keeps an edit all-or-nothing). Two items editing one paragraph compose: the second sees the first's text and the operations are the diff of the final text against the original.
- **The check gate.** The original is checked once (`check.run_check` in `<project>/respond-gate/`, a project of its own so the real project's cache, event log and shadow git are untouched), the staged copy with all edits is checked once more. A paragraph is dropped (its items become `author`) when the writer did not produce exactly its intended text, or when the staged check has an error in it that the original did not (compared by count per `(check, paragraph, kind)`). Only the changed paragraphs gate; a new error elsewhere (the abstract losing a number, say) is not attributed to an edit. Offline tier-0 checks make the gate; with `--results --model` the numbers check joins, with the network the citations check.
- **Replies and resolving.** One `Reply` per thread, at its root, after the edits. Nothing here writes `w15:done`: a human comment is never resolved. An author-category review point with a located passage also gets an anchored comment. The writer refuses a reply to a comment with no body anchor; that shows in `operations_refused` and exit 4.
- **Decision model.** `--decision-model` (needs `--model`) asks one `choice` question per item and its top category is the category (no thresholds). `author` and `done` get templated replies with no language-model call; `edit` and `answer` still use the language model for the quote and the text. A decision-model failure raises. Without the flag the language model triages.
- **Collaborators' own edits.** Before it writes anything, the run reads `view/paragraphs.json` of the project's shadow git (the text view the last `check` or `respond` read), finds the paragraphs of the current view with no matching run in it, and turns the baseline check's errors in those paragraphs into comments ("Changed since the last look."). The run then snapshots the document it read (the input, not the copy). The first run has no snapshot and says so. A project folder is per input file name, so working on the copy needs `--project` pointing at the same folder.
- **Sequential model calls**, through `compose._call.call_model`, logged by `ActionLog` in `<project>/log.jsonl`; the report's call and token counts are the records added by the run.

## Limits

- One paragraph per edit; a request that needs a new paragraph, a table or a figure goes to the authors.
- A review point that concerns the document as a whole is `author`, `answer` or `done`, never `edit` (no locatable passage).
- Context for triage is the whole document as numbered paragraphs up to 40000 characters; longer documents get the headings plus the paragraphs sharing the most words with the item.
- The comment text is data in the prompts, and the prompts say so, but nothing else defends against a comment that tries to steer the model; the gate and the verification are what bound the damage (an edit is a tracked change in a copy).
